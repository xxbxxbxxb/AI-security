## 二、前一天高信号动态

### 1. Google GTIG：对手从提示词转向多 agent 自动化，供应链和 AI 资产成为主战场

**事实**

- Google Threat Intelligence Group 于 2026-09-08 发布《From Prompting to Autonomy – The Evolution of Adversarial AI》，基于 Mandiant 事件响应、威胁追踪和平台防御遥测总结 2026 年第二季度观察。
- GTIG 称，曾观察到攻击者先侵入云资源，再在不到 6 小时内规划、构建并执行 agent-enabled 大规模凭证收集活动；攻击流程能够自动排错、轮换 IP，并降低人工介入延迟。
- 报告将攻击面扩展到 AI 软件生态：MCP server、模型权重和格式、推理/服务引擎、向量数据库、AI coding assistant 和 LLM security scanner 都可能成为供应链入口。
- GTIG 还报告 UNC6780/TeamPCP 相关活动：包括投毒 MCP fork、修改组织 GitHub 仓库、从 GitHub Actions runner 进程获取 OIDC token、发布带有效 SLSA 证明的恶意包，以及用隐藏工作区目录和配置文件影响 AI 助手。
- 报告指出攻击者正在窃取模型源码、提示词、API 凭证，劫持云环境运行未授权高性能 AI workload，即 LLMjacking。

**主要观点**

- AI 安全的边界已从“模型是否输出危险内容”扩展为“模型和 agent 是否被嵌入一个可被供应链操纵的执行系统”。
- 代码签名、SLSA attestation 或自动信任检查如果只验证发布身份，不验证构建来源和运行时行为，可能给恶意包提供更强的伪装能力。
- 防守方需要把 AI 端点、MCP 网关、模型仓库、CI/CD、云身份和开发者工作区作为一个联合攻击面盘点。

**创新点**

1. 把“提示词—agent loop—凭证—供应链—云算力”连成完整攻击链，体现从 LLM misuse 到 AI-enabled intrusion 的范式变化。
2. 将 AI coding assistant 的隐藏配置和 CI/CD OIDC token 纳入同一供应链威胁模型。
3. 从防守角度提出模型级 safeguards、威胁情报、主动打击和 containment 的组合式架构，而不是只依赖模型拒答。

**可信度与局限**

- 可信度：A-（Google/GTIG 官方威胁情报，基于 Mandiant 和平台遥测）；对报告所观察到的活动可信度较高。
- 局限：报告使用“观察到”“评估为”等威胁情报表述，公开材料不一定给出全部样本、受害者或可复现实验；不能据此推断所有攻击者都已具备同等自主能力。

**对研究生学习/进大厂的价值**

- 把 SBOM、SLSA、OIDC、GitHub Actions、MCP、模型注册表和云 IAM 放入 AI 安全学习路线，形成软件供应链与模型安全交叉能力。
- 作品集可实现一个“AI 依赖准入门”：扫描 MCP/模型/包的来源、签名、构建证明、隐藏配置、网络权限和运行行为，再决定是否允许 agent 使用。

来源：
- [Google Cloud/GTIG：From Prompting to Autonomy](https://cloud.google.com/blog/topics/threat-intelligence/from-prompting-to-autonomy-the-evolution-of-adversarial-ai)

### 2. OpenAI：用 500 万美元支持青少年 AI 影响与安全研究

**事实**

- OpenAI 于 2026-09-08 宣布投入 500 万美元，支持独立研究生成式 AI 对 13—17 岁青少年生活和发展的影响。
- 资助主题覆盖情绪与社会发展、不同年龄/文化/语言/社会经济背景差异、年龄适配设计、技术干预、AI 素养、家长/教育者支持和政策评估。
- 涉及未成年人的项目需要说明知情同意/同意、隐私与数据安全、风险披露、伦理审查以及发生伤害或紧急风险时的响应方式。

**主要观点**

- AI 安全证据不能只停留在模型拒答率和红队成功率，还要测量真实用户、发展阶段和使用情境中的长期结果。
- “对未成年人安全”是社会技术问题：产品设计、监护支持、学校环境和模型护栏共同决定风险。

**创新点**

1. 把年龄、文化和使用目的作为安全评测分层维度，而不是将青少年用户视为统一人群。
2. 将技术 safeguards 与行为、公共健康和人机交互研究结合，推动从模型中心评测转向结果中心评估。

**可信度与局限**

- 可信度：A（官方资助公告）；它确认了资助方向，不代表相关干预已经有效。
- 局限：资助项目尚未产出结果；研究涉及未成年人，样本获取、伦理审查和跨文化可比性会显著影响结论。

**对研究生学习的价值**

- 可关注“年龄适配安全评测”“长期依赖/过度使用”“AI 对社会情绪发展的影响”“多语言安全干预”等交叉课题。
- 做涉及人的研究时，先建立数据最小化、伦理审查、风险升级和退出机制，不能把安全研究当成普通 benchmark。

来源：
- [OpenAI：Funding grants for new research into AI and teen development](https://openai.com/index/teen-development-research-grants/)

### 3. AI for Science：GPT-5.6 Sol 参与超导量子芯片校准

**事实**

- OpenAI 于 2026-09-08 发布 MIT EQuS 研究生使用 GPT-5.6 Sol + Codex 辅助量子实验的案例。
- agent 连接实验室软件后，可运行测量、分析结果、选择下一组参数，并在六量子比特芯片上完成跃迁频率、脉冲校准和相干时间等常规测量。
- 在信号清晰、流程定义明确时，agent 可以少量人工介入完成标准测量；遇到弱信号或噪声时，寻找参数更慢且需要经验研究员指导。

**主要观点**

- AI for Science 的近期落点不是“模型替代科学家”，而是把重复测量、参数搜索、结果整理和实验软件控制接入闭环，让研究者把时间投入到实验设计和解释。
- 科学 agent 的安全核心是实验边界：允许的参数范围、设备状态、异常停机、可追溯日志和人类确认点必须显式编码。

**创新点**

1. 将 LLM agent 接入真实实验控制软件，形成“测量—分析—下一步测量”的闭环，而非离线问答。
2. 通过对清晰信号和弱/噪声信号的对比，暴露 agent 在不确定物理反馈下的能力边界。

**可信度与局限**

- 可信度：B+（官方案例，有具体实验流程描述）；它是产品/研究案例而非独立对照实验。
- 局限：案例规模小，任务有明确技能说明；不能推断 agent 已能处理开放式实验设计或安全关键设备。

**对研究生/求职的价值**

- 学习 Python 实验控制、数据质量检查、主动学习/贝叶斯优化和实验日志设计，能把 AI 能力落到真实科研管线。
- 任何连接硬件或生产系统的 agent 都要加入模拟器、权限白名单、dry-run、异常阈值和人工急停。

来源：
- [OpenAI：How GPT-5.6 Sol helps run quantum computing experiments](https://openai.com/index/codex-quantum-computing-experiments/)

### 4. ChatGPT Images 2.5：更强多模态能力配套多层安全栈

**事实**

- OpenAI 于 2026-09-08 发布 ChatGPT Images 2.5，并同步公开 GPT-Image-2.5-Sunburst/Flare 安全卡。
- 安全卡指出，更高真实感增加了现实人物、政治、性内容和敏感事件深度伪造风险；因此采用提示文本、输入图像、提示与图像联合分析、生成后检查以及线上/离线监控等多层防护。
- 官方自动化对抗评测中，Sunburst 的 unsafe generation presented 为 1.09%，Flare 为 1.41%，ChatGPT Images 2.0 基线为 1.64%。官方特别说明测试提示是刻意设计的违规样本，不代表生产流量发生率。
- 安全卡还称两种 2.5 图像模型没有跨越其 Bio High 或 Cyber High 阈值；这只适用于该模型能力分类，不代表所有滥用风险为零。

**主要观点**

- 多模态安全需要在输入、生成和产品交互三个位置同时控制；只做文本审核无法覆盖图像编辑和现实人物深度伪造。
- 公开残余漏放率比单一“安全通过率”更有决策价值，但必须连同测试集构造、类别分布和统计显著性一起解释。

**创新点**

1. 将图像级分类器、文本级提示安全、输入图像审核和生成后审查组合为端到端安全栈。
2. 从原始 taxonomy matching 转向更贴近实际产品危害的 outcome-based evaluation。

**可信度与局限**

- 可信度：A-（官方安全卡，指标定义清晰）；数字仍是厂商内部评测，需第三方红队和生产监测验证。
- 局限：刻意违规提示集与真实用户分布不同；1% 左右漏放率不能直接转化为现实伤害概率。

来源：
- [OpenAI Deployment Safety Hub：ChatGPT Images 2.5 System Card](https://deploymentsafety.openai.com/chatgpt-images-2-5/safety-evaluations)
- [OpenAI：Introducing ChatGPT Images 2.5](https://openai.com/index/introducing-chatgpt-images-2-5/)

### 5. DGEval：高风险法规知识 benchmark 暴露“会答题但不会安全操作”

**事实**

- National Cargo Bureau 与 Durham University 于 2026-09-08 公布 DGEval，用于评测 LLM 对国际海运危险品规则（IMDG Code）的理解。
- DGEval 测试 6 家提供商的 13 个模型、1,678 道题，覆盖选择题、开放问答、危险品清单查询和法规条款召回。
- 公告称最高模型在选择题上得分 95.8%，但配载和隔离问题在所有模型中明显更弱，平均比分类/文档题低约 35 个百分点；要求模型指出支撑答案的具体法规条款时，平均只有 14.2%。联网搜索提高结构化清单查询准确率约 25 个百分点，却对选择题推理帮助有限。

**主要观点**

- 高风险领域中，“答案看起来正确”与“能给出可审计、可执行、可追责的规则依据”是两种不同能力。
- RAG 或联网搜索可以改善查表，但不能替代对冲突规则、上下文条件和操作约束的推理验证。

**创新点**

1. 将 recall、开放式解释、结构化 lookup 和法规依据召回放在同一 benchmark 中，拆开测量知识、工具使用和证据能力。
2. 通过领域安全任务暴露通用模型在“操作性知识”上的隐性短板。

**可信度与局限**

- 可信度：B+（研究合作方公告，论文为预印本）；结果有明确任务设置，但尚待论文细节、数据集审查和独立复现。
- 局限：危险品海运是单一领域；模型版本、提示模板、联网工具和人工基线都会影响分数。

**研究/求职动作**

- 学习设计高风险 benchmark 时加入“答案 + 证据 + 适用条件 + 不确定性 + 升级人工”的输出格式。
- 可把 DGEval 思路迁移到网络安全合规、隐私法规或软件供应链政策，训练面向企业的可审计问答系统。

来源：
- [National Cargo Bureau：DGEval benchmark](https://natcargo.org/dgeval/)
- [arXiv：Evaluating Large Language Model Performance on International Maritime Dangerous Goods Code Compliance](https://arxiv.org/abs/2608.21036)

## 三、综合判断与主要创新点

1. **攻击自动化与防守自动化进入同一速度竞赛。** GTIG 报告把“低人工延迟、自动排错、凭证收集”描述为现实观察；防守侧必须把凭证撤销、CI/CD 冻结、云账号隔离和告警升级做成自动化 playbook。
2. **AI 供应链成为模型安全和软件安全的交汇点。** MCP、模型包、AI 依赖和隐藏配置既是开发效率工具，也是 prompt injection、恶意 hook、OIDC token 窃取和持久化的载体。
3. **高风险评测应从能力分数走向可执行证据。** DGEval 的法规召回差距说明，领域模型需要给出出处、适用条件和人工升级路径，不能只报准确率。
4. **AI for Science 的真实价值在闭环自动化，但安全边界必须先于自动化。** 实验 agent 适合清晰、可回滚的流程；面对噪声和异常时必须退回经验研究员。
5. **多模态安全正在采用端到端产品评测。** Images 2.5 的安全卡展示了输入—生成—输出—监控的全链路思路，也提醒我们要同时关注漏放率与真实生产分布。

## 四、今天适合执行的学习/项目动作

- 构建一份 AI 供应链资产清单：模型、MCP server、Python/npm 包、Docker 镜像、GitHub Actions、OIDC token、云端点和隐藏工作区配置。
- 写一个最小化的 agent supply-chain gate：在 agent 使用依赖前检查来源、SBOM、签名/SLSA 证明、仓库 hook、网络权限和可疑 prompt 配置。
- 为一个高风险领域设计 30 道“答案+证据+适用条件”题目，比较纯模型、RAG、联网检索和人工复核四种设置。
- 在实验室或模拟器中测试“测量—分析—下一步” agent，只允许白名单参数和 dry-run，记录噪声输入下的退避与人工升级率。
- 复现图像安全卡的指标设计：将 unsafe shown、blocked 和 safe generation 分开统计，并按政策类别、攻击方式和输入模态切片。
- 求职材料增加一项“供应链与运行时安全”内容：不仅说明模型效果，还说明凭证如何隔离、依赖如何验证、agent 如何停止、日志如何审计。
