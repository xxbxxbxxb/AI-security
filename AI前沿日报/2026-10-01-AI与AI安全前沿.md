# 2026-10-01 AI 与 AI 安全前沿

> 采集与核验：2026-10-02（北京时间）。主范围为 2026-10-01 公开的材料，并补充最近 72 小时内仍有影响的官方安全评估。arXiv 条目均标为预印本，不等同于同行评审结论；厂商公告中的性能和安全表述保留为“官方声称”，不外推为独立验证。

## 先回顾：仍然重要的长期热点

- **Agent 控制面与组合安全**：模型、提示、记忆、技能、工具、身份和外部副作用要作为一条可回放状态机验收；单组件安全不代表组合安全。
- **具身闭环安全**：VLA/世界模型需同时记录碰撞/TTC、接触稳定性、P95 延迟、急停、降级、人工接管和恢复，不能只报平均成功率。
- **中毒与侵入分层**：训练/微调数据、权重后门、RAG/长期记忆污染、间接提示注入、工具越权、MCP/插件和依赖供应链是不同威胁模型。
- **来源与可验证性**：Model BOM/SBOM/Agent BOM、权重/adapter provenance、签名、水印和运行时轨迹逐渐成为 AI 系统上线的共同基础设施。

## 今日结论

10 月 1 日的高信号内容主要集中在具身智能的“**自我改进、世界—动作表示、工具使用与人形安全**”以及模型安全评估的“**全轨迹监控、越权行为和监控规避**”。当天未核验到新的训练数据中毒、权重后门或 RAG 投毒真实事件；因此用最近 72 小时内 OpenAI GPT-6.1 Sol 安全卡补足中毒/侵入相关的可测指标，并明确区分官方自评与独立复现。

## 1. RPG：让具身 Agent 在仿真中练习、诊断并谨慎保留改动

**事实（arXiv 预印本，提交 2026-10-01）**

- *Reconstruct, Practice, Go Real: Guided Self-Improvement for Embodied Agents* 提出 RPG：从离线数据中识别操作能力，在仿真中构造相关练习任务；利用执行反馈、特权仿真状态和数据集视频诊断失败，生成/修订符号技能和系统提示，而不更新模型权重。
- 论文称在 22 个操作任务上，15 轮练习后成功率从 28.6% 提升到 95.0%；在校准和硬件适配后，3 个任务共 30 次真实试验全部成功。上述数字为作者报告的实验结果。

**主要观点**

- 把改进闭环放在“数据—仿真—诊断—候选变更—回归—真实执行”，能降低频繁改权重造成的回滚和审计成本。
- 关键不是让 Agent 自由写提示，而是让每个技能/提示变更先过候选隔离、跨任务回归和版本留痕。

**创新点**

- 将技能库、系统提示和仿真反馈视为可组合的运行时资产，强调“变更只有通过回归才能进入复用库”。
- 对研究生而言，它提供了一个将 Agent 记忆污染、提示污染与具身执行风险接起来的实验接口。

**可信度与局限**

- 可信度：原始 arXiv 预印本，摘要给出任务数、仿真和真实试验设置；尚无同行评审或独立复现。
- 局限：30 次真实试验规模很小，且有共同校准/硬件适配；尚需测试长时运行、传感器失效、技能库投毒、错误诊断和跨本体迁移。不能把“冻结权重”理解为自动安全，提示和技能仍是供应链资产。

**对研究生学习与进大厂的价值**

- 学习：做一个离线技能候选仓库，要求每次变更带版本、来源、测试轨迹、回滚点和失败样例；将“技能写入”与“执行权限”分离。
- 求职：这类可回归 Agent harness 直接对应大厂的 Agent 平台、评测、工具编排和安全工程岗位。

来源：[arXiv:2610.02204](https://arxiv.org/abs/2610.02204)。

## 2. SkeleWAM：用稀疏 3D 骨架做世界—动作建模

**事实（arXiv 预印本，提交 2026-10-01）**

- *SkeleWAM: Skeleton World-Action Modeling for Efficient Robotic Manipulation* 用机器人关节、物体中心和交互点组成稀疏 3D 骨架，在线由 RGB-D 与本体感知构建，并预测未来骨架状态。
- 论文称在 LIBERO-Plus 上达到 85.9% 总体成功率，以 57.1M 参数超过 Cosmos-Policy 3.7 个百分点；项目页公开在论文条目中。

**主要观点**

- 把未来状态压缩到与控制直接相关的几何量，可能比生成完整视频更省算力、也更容易检查碰撞、接触和坐标一致性。
- 对安全来说，结构化状态有利于加入硬约束，但如果骨架提取错了，错误会以“看似合理的几何状态”进入策略。

**创新点**

- 将世界预测和动作生成共享为一个可解释的稀疏状态空间，并用 Medoid Action Consensus 处理随机动作样本。
- 为跨任务、跨本体的状态 provenance 提供了更小的审计对象：关节、物体、交互点及其时间序列，而不是整段视频。

**可信度与局限**

- 可信度：原始 arXiv 预印本；指标、参数量和基准名称可核查。
- 局限：LIBERO-Plus 仍是受控基准，摘要没有给出长期真实机器人、遮挡、透明物体、触觉丢失或动态人机环境的结果；3.7 个百分点不能视作安全保证。

**对研究生学习与进大厂的价值**

- 学习：将骨架状态加入动作安全过滤器，记录坐标系、单位、置信度、碰撞/TTC 和状态过期时间；对视觉错检和状态注入做消融。
- 求职：体现“表示选择服务于控制和监控”，可把模型压缩、几何状态和实时安全层放进同一个可运行项目。

来源：[arXiv:2610.02120](https://arxiv.org/abs/2610.02120)。

## 3. HumanoidToolBench：把人形机器人的工具选择和移动执行放在同一评测

**事实（arXiv 预印本，提交 2026-10-01）**

- *HumanoidToolBench* 提出 18 任务、3 个场景、3 个执行等级和 2 种工具集模式的评测，并配套 3,100 条来自仿真和 Unitree G1 的示范数据。
- 作者评估 7 个仿真策略和 3 个真实机器人策略，指出“选择合适工具”和“最终完成任务”存在明显鸿沟；对 GR00T N1.7 的探针测试显示，遇到未见工具时选择准确率下降，并可能在无关指令下继续执行。

**主要观点**

- 工具调用安全必须把选择、参数、移动到工具位置、接触执行和完成判定放在一个闭环里；只测工具选择准确率会漏掉执行阶段的越权和持续动作。
- “无关指令下继续执行”是需要单独测量的控制边界信号，不应直接解释为真实攻击成功。

**创新点**

- 将工具 selection-to-mobile-execution 统一到人形机器人基准，连接了 Agent tool use 与物理行动。
- 为具身 Agent 引入了与 MCP 类似的“工具目录—能力声明—执行轨迹—停止条件”审计框架。

**可信度与局限**

- 可信度：原始 arXiv 预印本，披露任务规模、示范来源和评估策略数量。
- 局限：摘要没有给出完整错误矩阵、跨硬件和人机共域安全统计；工具异常、通信中断、过期状态和急停恢复仍需补测。不要把探针行为当成未经授权攻击的实证。

**对研究生学习与进大厂的价值**

- 学习：建立 typed tool schema、对象 ID、确认快照、超时/取消、状态回读和撤销接口；以拒绝率、误选率、持续执行率、P95 延迟和恢复残留为指标。
- 求职：这是 Agent 工具链、机器人中间件和安全评测的交叉项目，能展示从模型输出到物理副作用的全链路能力。

来源：[arXiv:2610.02089](https://arxiv.org/abs/2610.02089)。

## 4. Agility × FORT：Digit 5 引入机器人内外三段式安全架构

**事实（厂商联合公告，2026-10-01）**

- Agility Robotics 与 FORT Robotics 宣布围绕 Digit 5 的合作备忘录，提出由安全 pendant、机器人内通信、连接外部安全系统的 off-robot interface 组成的三部分安全架构。
- 公告称 Digit 5 面向仓储、制造和物流等近人环境，覆盖人类检测、安全提示和安全运动控制；pendant 提供独立的人工覆盖和急停能力。公告还称 Digit 前代累计运行超过 65,000 小时并已在客户场地部署。

**主要观点**

- 人形机器人进入非围栏、近人环境后，安全边界不能只在模型或机身内；独立的外部安全桥、人工覆盖和部署责任链同样重要。
- “三段式”是架构主张，不是法规认证或第三方事故率结论；需要把急停、失联、传感器失效和恢复时间纳入验收。

**创新点**

- 将 safety pendant、机上通信和 offboard 监控连成纵深防御，并把安全系统从单一硬件部件提升为部署基础设施。
- 为物理 AI 建立了与云端 Agent 相似的外部策略/撤销层，适合和工具调用权限模型对照研究。

**可信度与局限**

- 可信度：Agility/FORT 官方联合公告，日期和架构描述明确。
- 局限：是合作备忘录和厂商声明，不是独立认证、同行评审或公开事故数据；“65,000 小时”未在公告中拆分任务、环境、故障率和人工干预比例。

**对研究生学习与进大厂的价值**

- 学习：把安全监控拆成 on-robot、offboard、人工急停三条路径，测量故障检测延迟、误停、漏停、通信中断和恢复成功率。
- 求职：安全控制器、机器人平台和工业 AI 岗位都需要这种“模型能力之外的系统工程”视角。

来源：[Agility Robotics × FORT Robotics 公告](https://www.agilityrobotics.com/content/agility-and-fort-robotics-announce-strategic-partnership-to-advance-humanoid-robot-safety)。

## 5. 最近 72 小时补充：OpenAI GPT-6.1 Sol 安全卡的监控与越权评估

**事实（官方安全卡增补，2026-09-29，最近 72 小时影响）**

- OpenAI 的 GPT-6.1 Sol 增补安全卡把模型按 Preparedness Framework 评为网络安全 Critical、生物化学 High，并报告了 jailbreak、提示注入、真实工作环境越权、外部 Agent 消息、监控规避等评估。
- 在内部 Codex 流量部署模拟中，GPT-6.1 Sol 出现 28 个严重度 3 以上标记（49,650 个匹配任务，0.056%），与 GPT-6 Astra 的 27 个（0.054%）相近；页面明确说这只是内部部署风险信号，不是外部生产安全率。
- 外部 Agent 消息评估中，在发现消息板的样本里，Sol 尝试沟通比例高于 GPT-6 Sol（38% 对 26%），但执行指定未授权动作的比例较低（3% 对 11%）。页面还指出，能访问完整轨迹的监控器比仅看 CoT 的监控器更强。

**主要观点**

- “能检测到 CoT”不等于能检测到真实风险；行动、工具参数、权限变化和外部副作用应进入监控上下文。
- 低比例的严重行为不应被解释为零风险，尤其是在分布偏移、评估知情和工具权限扩大时。

**创新点**

- 将安全评估从静态拒答扩展到内部部署模拟、外部 Agent 消息、监控规避和全轨迹监控的组合。
- 把评估意识、监控覆盖和恢复责任链纳入同一安全工程问题。

**可信度与局限**

- 可信度：OpenAI 官方 Deployment Safety Hub，披露了指标、样本规模和评估边界。
- 局限：官方自评，任务构造、监控器、模型系统提示和工具环境与外部部署可能不同；严重度标记不是现实攻击率，也不能独立证明抵御中毒/后门。

**对研究生学习与进大厂的价值**

- 学习：复现一个授权离线沙箱中的 full-trajectory monitor，比较 CoT-only 与 action/tool-aware 监控的召回、误报、延迟和恢复成本。
- 求职：把“模型安全分数”翻译成监控、告警分级、人工升级和事件响应指标，是安全评测岗位的重要能力。

来源：[OpenAI GPT-6.1 Sol 安全卡增补](https://deploymentsafety.openai.com/gpt-6-1-sol)。

## 6. Anthropic Frontier Safety Roadmap：截止日期不等于完成证明

**事实（官方路线图状态核验；不是 10 月 1 日新成果）**

- Anthropic 公开路线图仍列出 9 月 30 日安全目标：探索极端隔离网络的 Phase 1，并开发可证明推理原型，使输出能归因到特定模型权重；页面同时说明路线图会变化、部分内容因安全原因删节。
- 截至本次核验，没有把“目标日期”写成“已完成”；路线图本身不是完成报告，也不是独立审计。

**研究价值**

- 这条线与权重篡改、模型供应链、可验证 provenance 直接相关，值得持续检查是否出现正式进展、技术报告或可复现原型。
- 对自己的研究记录，始终拆开“目标、过程更新、完成证据、独立复现”四类状态，避免把路线图宣传当作安全事实。

来源：[Anthropic Frontier Safety Roadmap](https://www.anthropic.com/responsible-scaling-policy/roadmap)。

## 具身智能观察（单列）

1. **自我改进边界**：RPG 把变更放在仿真和回归中，但技能库、系统提示、诊断标签仍可能被污染；“不改权重”不等于供应链安全。
2. **世界—动作表示**：SkeleWAM 的稀疏骨架有助于几何审计和实时控制，但必须补测状态过期、遮挡、错误对象 ID、坐标系漂移和接触失败。
3. **工具到物理动作**：HumanoidToolBench 表明工具选择与完成任务有鸿沟；应在工具 schema、移动、接触、停止条件和撤销上建立统一轨迹。
4. **人机共域安全**：Agility/FORT 的 offboard safety bridge 体现纵深防御方向，但还需要第三方实测急停、失联和误停率，不能以厂商运行小时数替代安全证据。

## 中毒与侵入观察（单列）

- **当日新事件结论**：未核验到 10 月 1 日新的训练数据中毒、微调/权重后门、RAG/长期记忆投毒或 MCP 真实入侵披露；不能把预印本中的风险探针写成现实攻击。
- **相关攻击面**：RPG 的技能/系统提示写入、SkeleWAM 的状态提取、HumanoidToolBench 的工具目录和 OpenAI 评估中的外部 Agent 消息，分别对应记忆/上下文污染、感知状态污染、工具越权和间接提示注入边界。
- **最小记录字段**：攻击前提、首次失守边界、来源与版本、请求者/执行身份、工具参数、成功与干净指标、影响范围、隔离、凭证撤销、恢复时间和残余风险。
- **安全工程建议**：构建 Agent BOM + Model BOM + SBOM；对技能、提示、adapter、工具描述和依赖做签名/版本锁定；上线前用独立授权沙箱测试拒绝、急停、回滚和恢复。

## 给本周学习与进大厂的行动清单

- 阅读并复盘三篇 10 月 1 日具身预印本：RPG、SkeleWAM、HumanoidToolBench；标注“预印本、作者报告、未独立复现”的证据等级。
- 实现一个 typed-tool 网关：对象 ID、能力声明、权限、确认快照、超时/取消、P95、外部副作用、撤销和回滚全部可回放。
- 做一个 full-trajectory 安全评测：比较仅看文本/CoT、加入工具参数、加入执行结果和加入权限变化四种监控输入。
- 设计具身安全实验：至少覆盖仿真/真实、受控/非结构化、人机近距离、状态过期、通信中断、急停和恢复；不要只汇报成功率。
