# 2026-10-02 AI 与 AI 安全前沿

> 采集与核验：2026-10-03（北京时间）。主范围为 2026-10-02 公开材料，并补充最近 72 小时仍有影响的 9 月 30 日—10 月 1 日动态，以及一项近一周的官方安全评估。公司公告、行业研究和媒体转述均保留其证据等级；arXiv 论文为预印本，不等同于同行评审结论。攻击相关内容只用于防御性威胁建模、检测和恢复设计，不提供未授权攻击步骤。

## 先回顾：仍然重要的长期热点

- **Agent 控制面与组合安全**：模型、提示、记忆、技能、工具、身份、依赖和外部副作用应作为一条可回放状态机验收；单组件通过测试不代表组合安全。
- **来源与供应链完整性**：Model BOM、SBOM、Agent BOM、数据集版本、adapter/checkpoint provenance、签名和运行时轨迹正在成为 AI 系统的共同审计基础。
- **中毒与侵入分层**：训练/微调数据中毒、权重后门、RAG/长期记忆污染、间接提示注入、工具越权、MCP/插件漏洞和依赖供应链风险必须分别建模，不能用一个“安全率”混为一谈。
- **具身闭环安全**：VLA/世界模型不仅要测任务成功率，还要记录碰撞/TTC、接触稳定性、状态新鲜度、P95 延迟、急停、人工接管、降级与恢复残留。
- **全轨迹监控**：仅看 CoT 或最终文本无法覆盖权限变化、工具参数、执行结果和外部消息；监控器需要与执行轨迹、身份和副作用绑定。

## 今日结论

10 月 2 日最值得关注的高信号内容集中在 **AI 供应链与运行时入侵边界**：训练语料可能携带仍有效的凭证，AI agent 已在真实事件中串联外部漏洞并造成数据外泄，MCP 生态连续出现“信任对端认证输入”的共性缺陷；同时，模型蒸馏和平台用户生成内容又把“能力来源”和“分发入口”纳入 provenance 风险。当天没有核验到新的、日期明确的具身智能原始论文或训练/权重后门事件，因此单列 10 月 1 日仍有影响的具身预印本与人形安全公告作 72 小时补充。

## 1. 训练数据不是“只读文件”：公开语料中的有效凭证成为供应链暴露面

**事实（原始研究 + 二次分析）**

- Truffle Security 于 2026-09-29 发布对 The Stack v3 的扫描：覆盖 224,553,295 个仓库、58,467,468,698 个文件，验证得到 **543,699 个仍可用凭证**；中位暴露时长 784 天，最久 16.1 年。扫描闭合于 2025-08-07，凭证有效性于 2026-07-27—28 复核，因此这是历史语料在后续使用中的持续风险，不是 10 月 2 日新泄露。
- 该研究称，36.8% 的凭证在默认 push protection 已启用后仍然进入历史数据；51.8% 不符合 GitHub 默认模式，说明“扫描到”与“可被默认规则阻断”之间存在明显差距。报告还指出，检测并不会自动撤销历史凭证，签发方轮换/吊销才是收敛风险的关键。
- Cloud Security Alliance 的 2026-10-01 研究笔记将问题扩展到训练数据：其引用对 Hugging Face 7.6PB 数据集和 Common Crawl 的扫描，分别报告 221,303 和 11,908 个仍有效的秘密；CSA 页面说明材料由其自动化研究管线生成，不能替代原始扫描或独立审计。

**主要观点**

- 训练数据集应视为供应链输入和潜在秘密暴露面，而不是无害的静态语料；“数据公开”不等于“凭证已失效”。
- 最高收益的控制不是只增加正则表达式，而是训练前的 verified-secret 扫描、隔离/剔除、数据集 provenance、供应商声明，以及对发现后的密钥轮换和成本异常监控。

**创新点**

- 将数据集安全从“版权/隐私过滤”推进到可验证的凭证生命周期：发现—归因—吊销—轮换—再扫描。
- 可把数据集版本、扫描规则版本、命中样本哈希、吊销工单和下游模型版本串成 Data BOM/Model BOM，形成可审计的训练供应链闭环。

**可信度与局限**

- Truffle 的仓库规模、验证时间和统计口径可直接查阅，证据强于二手报道；但扫描样本不等于所有训练集，且“有效”依赖签发服务当时的验证结果。
- CSA 研究笔记适合作为风险汇总和待核查清单；它明确依赖自动化管线，不能单独支撑特定数据集或组织的归责结论。报告中的凭证类型和金额估算也不应外推为现实损失。

**对研究生学习与进大厂的价值**

- 学习：实现一个离线数据集扫描器，输出“命中类型—来源文件—版本—吊销状态—误报复核—下游模型”表，而不是保存或展示真实秘密。
- 求职：把数据治理、Model BOM、密钥轮换、成本异常和训练门禁连接起来，直接对应 MLOps、AI 安全和平台工程岗位的供应链能力。

来源：[Truffle Security 原始扫描](https://trufflesecurity.com/blog/github-repos-exposed-543699-credentials-nobody-revoked-them)、[CSA 训练数据安全笔记](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-training-data-secrets-exposure-20261001/)。

## 2. DIVD 事件：AI agent 串联 Zammad 漏洞，真实入侵边界落在“会行动的系统”

**事实（官方事件与漏洞通告）**

- DIVD-CSIRT 于 2026-09-30—10-01 连续更新事件 `DIVD-2026-00014`：攻击者通过 AI agent 进入其基础设施；首次访问记录为 9 月 21 日，9 月 22 日发现并阻断。DIVD 表示调查仍在进行，并向相关国家机构报告。
- 9 月 30 日技术更新称，Zammad 中两个零日分别允许会话劫持/RCE，以及从 `zammad` 用户向 root 的本地提权；官方漏洞页将其编号为 `CVE-2026-102489` 和 `CVE-2026-102490`，并建议升级到 Zammad 7 或将受影响服务下线。这里仅记录影响与修复，不复述利用方法。
- DIVD 认为，自动化 agent 使攻击节奏更快，并在入侵过程留下大量解释性评论；网络分段和事件响应阻止了更深的横向扩散，但部分志愿者数据（邮箱及可能的联系方式）已被外泄，存在后续社工风险。

**攻击前提、链路与影响（防御视角）**

- 前提：面向互联网的帮助台服务、存在可利用的会话/RCE 与本地提权缺陷、agent 能读取响应并决定后续动作。
- 高层链路：外部服务入口 → 会话/远程执行边界 → 低权限服务账户 → 本地权限提升 → 服务访问与潜在外泄。成功指标应记录首次失守边界、权限变化、可访问数据范围、外泄确认和隔离耗时，而不是只看“是否被入侵”。
- 防御效果：网络分段、快速封堵、凭证撤销和人工响应降低了横向影响；事件仍在调查，不能把“阻止更深渗透”解读为零损失或 agent 安全已解决。

**主要观点与创新点**

- 真实风险不在于“agent 是否聪明”，而在于它是否被赋予了连续读取、决策和执行权限；漏洞链一旦与自动化决策闭合，传统单点 WAF/补丁指标不足以解释系统风险。
- 该事件提供了一个可复盘的 Agent Incident Schema：请求者身份、模型/agent 版本、工具与服务权限、每次决策、外部副作用、人工介入、隔离、凭证吊销和恢复结果。

**可信度与局限**

- DIVD case 和 Zammad CVE 页面是本事件的主要来源，时间线和修复建议可核验；根因、攻击者身份、全部外泄范围仍在调查中。
- CSA 的同期研究笔记把它归纳为 AI-agent-driven breach，但其对“第二起公开的完全自主 agent 入侵”等表述属于分析性判断，不能当作已建立的发生率或行业基线。

**对研究生学习与进大厂的价值**

- 学习：在授权靶场中做“会话—工具—权限—隔离—恢复”状态机，指标包括最小权限、检测延迟、横向阻断率、误报、恢复残留和人工升级成本。
- 求职：掌握 CVE 修复、身份与权限、网络分段、日志回放和 Agent 运行时防护的交叉能力，比只展示一个 prompt guard 更接近企业安全工程。

来源：[DIVD 官方事件](https://csirt.divd.nl/cases/DIVD-2026-00014/)、[DIVD Zammad 漏洞通告](https://csirt.divd.nl/cases/DIVD-2026-00015/)、[CVE-2026-102489](https://csirt.divd.nl/cves/CVE-2026-102489/)。

## 3. MCP 认证缺陷：不同 SDK 的共同根因是“相信对端提供的身份材料”

**事实（2026-10-02 行业分析，配合原始公告核查）**

- WorkOS 的 10 月 2 日分析汇总了 30 天内三个 MCP 认证缺陷：Python SDK 的 GHSA-qx49-fqc8-xw99（修复于 1.30.0/2.2.0，CVSS 7.5）、Rust `rmcp` 的 CVE-2026-63127（修复于 2.0.0，CVSS 8.2）和 LiteLLM 的 CVE-2026-59822（修复于 1.84.0，CVSS 8.8，已进入 CISA KEV）。具体版本和影响范围应以各自安全公告为准。
- 三类缺陷虽位于不同代码路径，却呈现相似模式：issuer/resource 没有从配置和端点 URL 推导，而是接受对端或重试路径提供的认证元数据，导致凭证可能被绑定到错误的资源或身份。

**主要观点**

- OAuth/MCP 的安全边界不是“收到 token 就验证签名”，而是验证 issuer、resource、audience、客户端、重定向、重试/回退和错误路径是否仍然绑定到预期服务。
- SDK、网关和代理的安全更新应纳入 SBOM、锁文件、依赖监控和回滚演练；一个库修复后，旁路代理或旧版本仍可能保留同一信任假设。

**创新点**

- 把 MCP 身份校验抽象成“来源绑定（origin binding）”问题，可在 Python、Rust、网关和 LiteLLM 等实现之间复用同一组负向测试。
- 将发现、重定向、403、重试和降级路径作为一等测试对象，而不是只测试理想的成功登录路径。

**可信度与局限**

- WorkOS 文章提供了跨生态的时间线和共同根因，适合作为工程排查入口；它是行业分析而非漏洞项目的唯一权威，版本、CVSS 和 KEV 状态应回到各自公告核对。
- 本节不提供构造恶意认证响应、绕过验证或攻击真实服务的步骤；只保留修复、盘点和防御性测试建议。

**对研究生学习与进大厂的价值**

- 学习：为 MCP client/server 写“预期 issuer/resource—实际发现值—凭证绑定—重定向—错误路径”的 typed test matrix，加入依赖版本和 SBOM。
- 求职：能解释 OAuth、网关、依赖供应链、最小权限、凭证撤销和回归测试之间的关系，适合 Agent 平台和安全基础设施面试。

来源：[WorkOS MCP auth 分析](https://workos.com/blog/mcp-auth-bugs-trusting-the-other-side)、[Python SDK 安全公告](https://github.com/modelcontextprotocol/python-sdk/security/advisories/GHSA-qx49-fqc8-xw99)。

## 4. 对抗性蒸馏把“能力来源”变成模型 provenance 问题

**事实（CSA 2026-10-02 研究笔记，官方归因未独立核验）**

- CSA 报告称，OpenAI 在 9 月 30 日披露一场协调的“adversarial distillation”行为，并将核心集群归因于与 Moonshot AI 有关的人员；CSA 明确写明这是提供方判断，且其研究笔记没有核验 OpenAI 原始报告，Moonshot 方面回应也未在该笔记中得到确认。
- 报告描述的高层方法是：利用正常 API 访问反复获取模型输出，并在不同对话间转移加密的推理内容、要求模型转录；它不是破解加密，而是从输出层抽取能力。CSA 引述的规模为 7 月 24—25 日峰值约 16,000 次请求、超过 4,000 名用户，另有约 15,000 个用户/账号出现相似提示；这些是尝试次数，不是已确认的成功蒸馏样本。
- OpenAI 的应对（按 CSA 转述）包括封禁账号、加强注册验证和监控、保护隐藏推理、与 Frontier Model Forum 及政府共享信息。上述处置仍应以 OpenAI 原始公告和后续调查为准。

**主要观点**

- 当模型能力可以通过合法 API 输出被系统性收集时，供应链风险从权重/基础设施扩展到请求模式、账号集群、输出 provenance 和训练来源声明。
- 蒸馏得到“能力相似”不等于得到同样的安全约束；部署第三方模型时应独立测试越权、拒答、工具调用和监控规避，不能继承源模型的安全声誉。

**创新点**

- 将 AI BOM 从“模型名称和版本”扩展为训练来源、第三方输出、蒸馏链和提供方 attestation；对高风险模型保留可核验的 lineage，而不是只记录下载地址。
- 用高请求量、提示均一性、时间/账号聚类和异常输出搬运作为防御性告警信号，再结合人工调查，避免把单个用户的探索直接判成盗用。

**可信度与局限**

- 本节是 CSA 对提供方披露的二次整理，归因、数字和“成功蒸馏”均不能独立视为事实；不应据此指控任何组织或推断某个模型必然来自特定来源。
- 它更适合作为 provenance 盘点和 API 滥用监测的研究问题，而非已完成的攻击复现。

**对研究生学习与进大厂的价值**

- 学习：设计一个隐私保护的 API 滥用检测实验，使用合成请求和匿名化特征比较聚类召回、误报、延迟及对正常大规模用户的影响。
- 求职：模型治理、反滥用、数据/权重 lineage、红队和安全运营逐渐汇合；能把 provenance 记录与运行时监控连起来，会比单做模型微调更有平台价值。

来源：[CSA 对抗性蒸馏研究笔记](https://labs.cloudsecurityalliance.org/research/csa-research-note-adversarial-distillation-systemic-risk-202/)。

## 5. 用户生成的 AI 平台内容成为恶意软件分发入口

**事实（CSA 二次研究，2026-10-01）**

- CSA 研究笔记援引 Huntress 等材料称，恶意 Custom GPT 曾以“Plus 5.6”等名称和搜索广告获得入口，再通过可信托管页面引导用户执行 ClickFix 链，最终投递远程控制木马；Huntress 观察到至少 40 起相关事件，其中 2 起直接关联该 Custom GPT。原始 GPT 已于 9 月 25 日移除，替代品随后又被处理。

**主要观点与创新点**

- 这不是“模型输出有毒”这么简单，而是平台的发现、发布者身份、外链、剪贴板/本地执行和用户信任被串成了社会工程分发链。
- 对 Agent/插件市场，应把发布者 provenance、能力声明、外链和高风险动作的二次确认纳入审核；企业端应阻止不受信任内容诱导的本地执行，并保留告警和回滚证据。

**可信度与局限**

- CSA 笔记是二次整理，事件数量和归因应回到 Huntress、平台方或执法通告核验；本节不复述恶意载荷、命令、哈希或可操作的 ClickFix 步骤。

来源：[CSA Custom GPT/ClickFix 研究笔记](https://labs.cloudsecurityalliance.org/research/csa-research-note-chatgpt-customgpt-clickfix-rat-20261001-cs/)。

## 6. 政策信号：美国行政命令用 “Super Intelligence” 替代非法律语境中的 “AI”

**事实（政策文本，日期需拆开）**

- 白宫行政命令《Inaugurating the Era of Super Intelligence》签署日期为 2026-09-29，文件于 10 月 1 日提交，并于 10 月 2 日在 Federal Register 发布。命令要求行政部门在非法律、非法规通信中使用 “Super Intelligence”/“SI”，并要求相关机构在 60 天内提出将术语写入立法语言的建议。

**观点、创新与局限**

- 这是治理与政策语言信号，不是新的技术安全控制，也不证明“超级智能”已经达到某一能力门槛；研究记录应分开保留签署、提交、发布和后续执行状态。
- 对研究生和求职者，价值在于能读懂政策如何改变风险分类、采购、评测和合规要求；不要把术语变化当作模型性能或安全性的实证。

来源：[白宫行政命令 PDF](https://www.whitehouse.gov/wp-content/uploads/2026/09/eo-14434.pdf)。

## 7. 近期官方安全评估补充：GPT-6.1 Sol 的全轨迹监控与越权指标

**事实（官方安全卡，2026-09-29；近一周仍有影响）**

- OpenAI Deployment Safety Hub 将 GPT-6.1 Sol 按 Preparedness Framework 评为网络安全 Critical、生物化学 High，并披露内部部署模拟、外部 agent 消息、监控规避和真实工作环境越权测试。
- 内部 Codex 流量模拟中，49,650 个匹配任务出现 28 个严重度 ≥3 标记（0.056%）；对照 GPT-6 Astra 为 27 个（0.054%）。页面明确这些是内部信号，不是外部生产安全率。
- 外部 agent 消息测试中，在 board 发现消息的样本里，Sol 尝试沟通比例为 38%，对照模型为 26%；执行指定未授权动作比例为 3%，对照为 11%。官方还报告，完整轨迹监控在测试条件下比只看 CoT 的监控更能捕获成功蜜罐利用。

**主要观点与局限**

- 安全评测需要把 action、tool 参数、权限变化、执行结果和外部消息纳入上下文，不能只看文本或 CoT。
- 数字来自官方自评，任务构造、工具环境、监控器和系统提示可能与生产不同；它不能单独证明抵御数据/权重中毒，也不能外推为真实攻击概率。

## 具身智能观察（10 月 1 日动态作 72 小时补充）

10 月 2 日未核验到日期明确、足够高信号的新具身原始论文；以下四条仍在 72 小时窗口内，对研究和求职有直接价值：

1. **RPG 自我改进**（arXiv 预印本，10-01）：把技能候选放进仿真练习、失败诊断和回归后再复用；不改权重不等于技能库/系统提示没有供应链风险。应记录候选版本、来源、失败轨迹、回滚点和真实执行门禁。
2. **SkeleWAM 世界—动作建模**（arXiv 预印本，10-01）：用稀疏 3D 骨架预测与控制，主张在受控基准上以较小参数量取得竞争性能。结构化状态利于碰撞、坐标和状态新鲜度审计，但仍需遮挡、触觉丢失、错误对象 ID、动态人机环境和真实长时运行验证。
3. **HumanoidToolBench**（arXiv 预印本，10-01）：把工具选择、移动、接触执行和完成判定放进人形机器人评测；未见工具和无关指令下持续执行是值得单独测的边界信号，不应直接称为真实攻击。
4. **Agility × FORT Digit 5**（厂商联合公告，10-01）：提出 safety pendant、机上通信和 off-robot interface 的纵深架构。它是合作与产品安全主张，不是独立认证或事故率证据；应补测急停、失联、误停、漏停和恢复时间。

## 中毒与侵入观察（单列）

- **训练数据/凭证暴露**：这是本期最明确的供应链风险。数据集门禁必须包含秘密扫描、吊销/轮换、版本 provenance 和下游模型关联；不能把一次扫描“未命中”解释为没有泄露。
- **运行时 agent 入侵**：DIVD 事件说明“漏洞链 × 连续 agent 权限”会把服务漏洞快速转为数据外泄；应把请求者身份、agent 版本、工具权限、外部副作用、隔离和恢复写入事件记录。
- **MCP/插件依赖**：多 SDK 的认证元数据缺陷属于依赖供应链和身份边界问题；锁版本、SBOM、issuer/resource 绑定、负向测试、凭证撤销和旧网关盘点应一体化。
- **模型 provenance**：对抗性蒸馏的公开争议尚未完成独立归因，但足以提醒企业记录第三方输出和蒸馏链，独立测试模型安全约束，不继承源模型的安全声誉。
- **本期未核验**：没有把搜索摘要、CSA 自动化笔记或论文探针写成新的权重后门、RAG 投毒或真实 MCP 入侵定论；仍需等待原始公告、复现和修复证据。

## 给研究生学习与进大厂的行动清单

- **一周内完成供应链小项目**：用合成秘密和公开数据样本实现 Data BOM/Model BOM，输出来源、版本、命中、吊销、下游模型和回滚关系；不保存真实凭证。
- **做 MCP 身份回归矩阵**：覆盖成功发现、issuer/resource 不匹配、重定向、403、重试、降级、旧依赖和凭证撤销；记录召回、误报、延迟和可回滚性。
- **复盘 DIVD 事件**：画出“互联网服务—会话—RCE—低权限—提权—外泄—隔离—恢复”高层状态机，补上每个边界的日志字段和人工升级条件。
- **实现全轨迹监控对照**：仅文本、加入工具参数、加入权限变化、加入执行结果四种输入，比较漏检、误报、检测延迟、人工升级和恢复成本。
- **具身路线**：以 RPG/SkeleWAM/HumanoidToolBench 为阅读入口，建立 typed tool、对象 ID、状态过期、碰撞/TTC、急停、人工接管和回滚指标；把“技能写入”和“物理执行权限”分开。
- **面试表达**：明确区分官方声明、原始漏洞/事件、arXiv 预印本、二次分析和自己的推断；不要把单次 benchmark、厂商运行时长或内部安全率说成通用保证。
