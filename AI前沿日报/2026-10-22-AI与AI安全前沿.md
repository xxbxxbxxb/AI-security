# 2026-10-22 AI 与 AI 安全前沿

> 核验窗口：北京时间 2026-10-22 00:00—23:59。官网只标日期的项目注明北京时间首发时刻未核；arXiv 以 v1 UTC 提交时刻换算。所有预印本数字为作者报告，不视为同行评审或独立复现。本期于 10 月 24 日补录。

## 仍然重要的长期热点

- Agent 的快速决策、工具授权和事后证据应分层：低延迟分类器可辅助路由，不能单独证明高后果操作安全。
- 持久记忆必须管到摘要、派生记录、删除后行为和跨会话召回；仅删原始记录不等于信息消失。
- 具身 Agent 评测需要把感知、预测、规划、执行和结果验证拆开，特别是物理后果与恢复。

## 今日高信号与观点

### 1. OpenAI Decisions API：把小决策做成低延迟、受限输出接口

- **事实**：[OpenAI 官方发布](https://openai.com/index/decisions-api/)标注 10/22，宣布 Decisions API 正式可用，基于 GPT-6 Luna，支持文本、图像和结构化输入，返回概率、给定选项或评分；厂商称相比同模型 Responses API 可快至 10 倍，并列出客户案例。页面未给精确首发时区。
- **主要观点**：Agent 工程可把大量重复的分类、路由、升级判断从长生成调用中拆出，降低热路径延迟和费用。
- **创新点**：为有界答案提供专门接口及批处理/缓存/实时语音集成，把“微决策”作为可独立评测组件。
- **可信度/局限**：速度和客户效果属于厂商/客户选择性材料；概率并非自动校准，也不代表可替代权限控制、确定性规则或人工批准。
- **学习/求职价值**：做同任务对照：准确率/校准、P95、费用、弃权率、语言/领域漂移以及安全误判；高风险动作仍由独立策略引擎阻断。

### 2. AgentTriage：跨运行时可重放的安全诊断

- **事实**：[arXiv:2610.30738](https://arxiv.org/abs/2610.30738) v1 为 10/22 05:09 UTC（北京时间 13:09）。作者将不同 Agent 运行时的调用、结果和策略证据规范化为类型化来源图；结论需引用具体事件，缺必需证据则弃权。论文报告五种运行时、120 个裁定案例的作者自评结果。
- **主要观点**：只看 Agent 最终回答无法诊断文件写入、代码执行或数据发送；审计需能重放和核查具体副作用。
- **创新点**：规范化事件 + 确定性生命周期连接 + 关键策略切片 + 证据绑定；把“无法判定”显式化。
- **可信度/局限**：预印本和指定运行时案例，观察接口不完整、日志真实性和策略 oracle 偏差仍可能限制结论。
- **学习/求职价值**：可做跨工具调用的统一审计 schema，把请求者、权限、参数、进程、结果及回滚证据串起来。

### 3. AfterDeleteBench：删除记忆后，衍生状态可能继续泄露信息

- **事实**：[arXiv:2610.31366](https://arxiv.org/abs/2610.31366) v1 为 10/22 14:41 UTC（北京时间 22:41）。作者用合成秘密比较“接触后删除”与“从未接触”的固定权重 Agent；报告删除原记录后仍能从摘要/分量重建秘密，而按来源追踪派生项并封闭删除可消除所测条件下的观测恢复。
- **主要观点**：删除是系统级行为属性，不是存储层单条记录操作。
- **创新点**：配对 never-exposed 基线、分量重建和回复解析误差审计，将隐私泄露与评分接口错误分开。
- **可信度/局限**：合成秘密和少数模型/存储形态，不推导真实用户泄露率或所有记忆架构的效果。
- **学习/求职价值**：给 RAG/Agent 作品加入来源图、派生摘要 TTL、删除闭包、旧缓存回归和跨会话探测。

## 具身智能单列观察

- [PAPAV 综述，arXiv:2610.30108](https://arxiv.org/abs/2610.30108) v1 为 10/21 17:52 UTC，即北京时间 10/22 01:52。**事实**：作者以 Perceive—Anticipate—Plan—Act—Verify 五功能比较计算机 Agent 与机器人，并称所查 64 个基准中预测/验证显式评测稀少。**创新点**：按能力而非架构划分。**局限**：综述统计取决于基准选样和分类，并非新机器人实测。**价值**：研究设计可单列预测质量和结果验证，避免任务成功率掩盖错误。
- [预测几何到动作，arXiv:2610.28164](https://arxiv.org/abs/2610.28164) v1 为北京时间 10/20 21:08，属于近 72 小时补读，不算 22 日新稿。作者将多视角几何时间演化与动作相关过渡分成互补表征，在 LIBERO、SimplerEnv 和真机任务报告收益；需追踪代码发布、部署偏移和接触安全。
- **物理安全观察**：本日一手材料未验证新的真实机器人失控事故；综述与预印本均不能代替接触力、碰撞、急停和恢复测试。

## 中毒与侵入单列观察

| 方向 | 前提/攻击链 | 指标与防御边界 |
|---|---|---|
| 邮件 Agent 钓鱼 | 攻击者可控邮件内容进入代理工作流，诱使越权响应 | [AgentPhishing，arXiv:2610.31404](https://arxiv.org/abs/2610.31404) v1 北京时间 10/22 23:07；作者报告九种 Agent 中部分系统传统钓鱼识别良好却对自适应请求脆弱。需同时测检测率与实际恶意请求遵从率；仅属受控基准 |
| 记忆残留/污染 | 原记录删除但摘要、分量或派生状态留下信息 | AfterDeleteBench 的配对未接触对照、来源闭包和新会话召回比“删除成功”API 返回值更有意义 |
| 运行时侵入取证 | 工具执行、日志字段和政策版本分散在多个运行时 | AgentTriage 要求事件证据、版本与策略 oracle 可重放；无证据应弃权，不做无依据归因 |

## 下步行动

1. 用合成邮件和合成秘密测 Agent 的检测、实际工具动作、删除后残留与审计可重放性。
2. 把受限决策接口置于路由层，策略引擎留在执行层；并行报告 P95、误拒、漏拦和费用。
3. 具身论文按 PAPAV 五功能建评测表，单独记录真机安全和恢复。
