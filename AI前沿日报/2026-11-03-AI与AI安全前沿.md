## 一、仍然重要的长期热点

1. **Agent 执行边界**：工具描述、技能包、检索内容和记忆都可能把“信息”变成“权限”；重点仍是身份贯穿、最小权限、动作前门禁、可撤销凭证、全局事件图和可重放恢复。
2. **RAG/记忆与供应链**：要同时审计原始来源、摘要/向量/缓存派生物、删除闭包和模型/依赖 provenance；“删除原记录”不等于秘密不可重建。
3. **具身智能闭环**：VLA、世界模型、跨本体数据和触觉正在从能力展示转向真机风险验收；必须报告接触/碰撞、急停、watchdog、P50/P95 时延、误拒/漏拦和恢复时间。
4. **评测可信度**：任务成功率、基准解析器和自动裁判可能掩盖副作用；安全评测应把可验证伤害、状态变化和实际工具结果纳入指标。

## 二、11 月 3 日高信号动态

### 1. OpenAI：Accelerating engineering for the physical world（官方发布，11 月 3 日）

- **事实**：OpenAI 介绍 GPT‑6/Astra 与 Codex 支持机械、电气、CAD、仿真和制造协同；公司称内部硬件团队过去一年按 token 计的模型使用量增长 23 倍，并展示一个由 Astra 协助完成外壳、PCB、软件集成的设备原型。OpenAI 同时承认生产公差、装配细节和制造限制仍需要多轮人工复核；其内部 BenchCAD 2.0 测试中，更新的内部模型平均分 0.875，Astra 最高推理设置为 0.594。
- **主要观点**：AI 在物理世界的近期价值更像“跨 CAD/ECAD/仿真/制造约束的工程协作者”，而不是无需监督的自动设计师。
- **创新点**：把多模态计算机使用、结构设计、PCB、固件和仿真放进同一工作流，并用制造可行性反馈形成闭环。
- **可信度/局限**：官方自述；BenchCAD 与内部团队案例的任务分布、基线和独立复现实验未公开，不能外推到安全关键产品或通用机器人控制。
- **对学习/求职的价值**：适合练习“需求→CAD/仿真→约束检查→人审→变更审计”流水线；作品应报告返工率、约束违例、人工复核点和失败恢复，而不是只展示生成速度。
- **来源**：[OpenAI 原文](https://openai.com/index/accelerating-engineering-for-the-physical-world/)

### 2. Google DeepMind：Agentic cheminformatics with Google Antigravity（官方发布，11 月 3 日）

- **事实**：DeepMind 展示 Antigravity 的 Cheminformatics Skills 从文献、图表和公共化合物数据中检索候选物，进行 matched molecular pair 分析并提出刚性化大环及合成路线；文章称单轮工作流可从数天压缩到约一小时，并明确提醒稀疏数据、实验噪声和窄动态范围限制预测精度，所有设计仍需合成和实验验证。
- **主要观点**：科学 Agent 的关键增益是把检索、结构化、候选生成和解释串成可审计工作台，速度提升不能替代实验闭环。
- **创新点**：以技能化工具连接文献抽取、反应验证、结构操作和下游预测，形成面向化学研究的可组合 Agent。
- **可信度/局限**：官方案例和产品说明，未提供独立盲测或失败分布；涉及生物/化学设计时应额外核查数据来源、越权工具、合成可行性和生物安全边界。
- **对学习/求职的价值**：可复现“来源记录→结构化提取→候选排序→不确定性→实验待办”小项目，重点展示 provenance、弃权和人工复核。
- **来源**：[Google DeepMind 原文](https://deepmind.google/blog/agentic-cheminformatics-with-google-antigravity/)

### 3. Boston Dynamics：Stretch Gen 2（官方发布，11 月 3 日）

- **事实**：Stretch Gen 2 面向物流卸货，基于超过 100,000 小时和数千万箱运行数据改造连接器、抓手、旋转关节、诊断和维护流程；公司称内部线缆减少 81%，最高可达每小时 1,000 箱，急停位置和外壳也作了防误触改动。
- **主要观点**：工业具身系统的竞争力越来越由可维护性、故障率、服务闭环和安全停机共同决定，而非只看单次抓取成功率。
- **创新点**：将硬件模块化、在线诊断、软件持续更新和 fleet-level world modeling 结合到部署后运维。
- **可信度/局限**：厂商发布，性能依赖箱体重量、堆叠整齐度、现场环境和维护条件；未提供独立第三方安全评测或长期故障分布。
- **对学习/求职的价值**：研究机器人安全时应把“软件更新—诊断—备件—急停—恢复”纳入系统威胁模型，形成可量化的 MTBF、恢复时间和误停机指标。
- **来源**：[Boston Dynamics 原文](https://bostondynamics.com/news/boston-dynamics-launches-next-generation-stretch-robot/)

### 4. AIRoA-0：仅用手持示范的跨本体长时操作（arXiv v1，11 月 2 日 UTC；北京时间 11 月 3 日）

- **事实**：论文报告使用 16,151 小时手持夹爪示范、全程不采集机器人数据、不用强化学习或机器人纠错；10 项任务平均成功率 78%，同任务示范上后训练的四个 VLA 基线中最好为 27%，测试时才出现机器人。
- **主要观点**：跨本体学习的瓶颈可从“为每种机器人重新采集遥操作”转向手持数据、腕部视觉和阶段建模；但精度和安全仍取决于末端执行器、接触动力学与部署分布。
- **创新点**：把手持 gripper 数据、腕部双目视觉、阶段预测和连续动作解码组合成 embodiment-agnostic 流程，并开放数据/权重/后训练配方。
- **可信度/局限**：arXiv 预印本，数字来自作者自建十任务评测；没有长期真机、异常接触、急停或跨硬件故障统计，不能把 78% 视为通用安全成功率。
- **对学习/求职的价值**：适合做“跨本体数据→行为策略→接触异常监测”的复现；应补充硬件在环、碰撞约束、P95 时延和失败回退。
- **来源**：[arXiv:2611.03815](https://arxiv.org/abs/2611.03815)

### 5. PanoTac：低成本三轴触觉与接触丰富操作（arXiv v1）

- **事实**：PanoTac 每个指尖提供 `12×32×3` 正向/剪切触觉、60 Hz、单指尖成本低于 50 美元；在试管准备、舀粮和倒盐任务上，作者报告相对纯视觉基线平均提升 46.7 个百分点，去掉空间接触信息或剪切反馈都会降低表现。
- **主要观点**：触觉不是视觉的附属信号，而是决定接触状态、力方向和恢复动作的独立观测通道。
- **创新点**：把低成本柔性传感器、三轴密集阵列和视觉—触觉策略整合到接触丰富操作。
- **可信度/局限**：预印本；任务规模、传感器漂移、跨批次标定、污染/磨损和真实安全边界尚需独立验证。
- **对学习/求职的价值**：可围绕触觉漂移、异常接触和传感器欺骗做安全评测，报告接触误报/漏报、恢复动作和控制延迟。
- **来源**：[arXiv:2611.03520](https://arxiv.org/abs/2611.03520)

### 6. 世界模型与移动机器人 sim-to-real（两篇 arXiv v1；其中一篇已标注 RA-L 接收）

- **Physical Experience Builds Continual Spatial World Models**：动态迷宫中用跨回合空间变化记忆和状态—动作—结果经验更新世界模型；有信息的历史变化能减少后续路线修正并迁移到未见变化，但拓扑正确不保证动作预测正确，物理经验仍需校正。论文为预印本。[链接](https://arxiv.org/abs/2611.04016)
- **A Practical Causal Framework for Autonomous Mobile Robots**：保留高层因果结构，只用少量真实观测更新参数，作者称在共享人类环境中实现快速 sim-to-real，并优于非因果基线；页面标注 **Accepted in IEEE Robotics and Automation Letters**，但完整实验细节仍需读正文。安全重点是把因果更新与人群环境中的在线约束、急停和回滚绑定。[链接](https://arxiv.org/abs/2611.04027)
- **主要观点/创新**：两者共同把“可修正的物理经验”置于世界模型核心，前者强调记忆不能压过当前证据，后者强调结构化因果迁移降低真实数据需求。
- **局限与价值**：均非大规模长期部署证明；研究生可做受控动态环境复现，加入传感器欺骗、分布外障碍、P50/P95 和恢复时间。

### 7. RoboScope Kit：把具身评测从慢脚本变成可扩展基础设施（arXiv v1）

- **事实**：论文把策略和各 benchmark evaluator 分别封装，在不改变原评分规则的前提下做并行调度；作者报告 LIBERO-Long 评测加速 4.45×（CUDA MPS 配置 6.16×），RoboTwin Easy 四卡 500 回合从单卡基线 25.04× 加速且成功结果、终止步一致。
- **主要观点**：可重复、可扩展的评测基础设施本身就是研究贡献；加速不应改变观测、动作和评分语义。
- **创新点**：按实测探针拆分模拟器 worker 与策略副本，确定性分片，并只渲染动作块需要的观测。
- **可信度/局限**：预印本，结果依赖硬件、并发和 benchmark 适配；速度提升不等于安全提升，仍需加入失效分类、接触约束和随机种子审计。
- **对学习/求职的价值**：适合做“统一评测适配器 + 安全回归套件”，把吞吐、成功率、失败模式和证据可重放性一起交付。
- **来源**：[arXiv:2611.03850](https://arxiv.org/abs/2611.03850)

## 三、中毒、侵入与安全评测观察

### 1. MCP Tool Poisoning：跨框架真实工具执行测量（arXiv v1）

- **攻击链/成功指标**：攻击者控制 MCP 工具描述、schema 字段或响应内容 → 污染模型上下文 → 触发攻击者工具调用 → 访问攻击端点 → 通过 canary HTTP 验证秘密外传。跨 12 框架、18 模型、45 场景的 9,720 个单元中，作者报告总体脆弱单元比例 22.9%；其中 64.9% 发起攻击者工具调用、23.0% 联系攻击端点、12.1% 可验证外传秘密，模型 ASR 介于 0.4%–49.7%。
- **主要观点/创新**：把“模型说了会做”升级为真实执行和外传证明，并给出 25 类根因；九个核心框架的差异不显著，说明风险更多由模型与输入共同决定。
- **防御效果/局限**：描述正则扫描器拒绝 45 场景中的 20 场，误报率 7.2%，且论文称框架没有主动防御；这是作者受控实验，工具、模型和 canary 环境不等于生产系统。
- **对学习/求职的价值**：在自有假工具和隔离网络中复现“描述注入→副作用→凭证撤销”，报告漏拦、误拦、P95 和恢复证据；不要针对第三方真实 MCP 服务测试。
- **来源**：[arXiv:2611.03555](https://arxiv.org/abs/2611.03555)

### 2. IAMRAGBENCH：RAG 中毒导致 AWS IAM 授权扩张（arXiv v1）

- **攻击链/成功指标**：攻击者控制检索上下文 → LLM 生成 provider-valid 的 IAM policy → 任务仍完成且越过预先定义的 authorization envelope → 新增原本禁止的请求权限。作者在 60 个案例、五个端点上报告 49 个精确授权差异，其中 46 个 goal-matched attack（46/292，15.75%）；BM25 从 720 份文档在 `k=5` 找到指定 poison，但端到端只产生 7/294（2.38%）goal-matched attack。
- **主要观点/创新**：把“语义上看似合理”与“权限包络是否扩张”拆开，用确定性授权和请求级检查判定攻击成功。
- **防御效果/局限**：论文是预印本、基准为合成案例；数字不代表真实 AWS 事故率。防御应让策略生成与权限审批分离，并在实际请求层做 deny-by-default 与边界校验。
- **对学习/求职的价值**：可做 RAG provenance + policy diff + 请求模拟器，演示“输入被污染但调用仍被硬门禁拦截”，只用自有云沙箱。
- **来源**：[arXiv:2611.03431](https://arxiv.org/abs/2611.03431)

### 3. RuntimeTickets：把 Agent Skill 变成可审计运行时义务（arXiv v1；提交 ICLR 2027 审稿）

- **事实/创新**：从任务交付契约生成带来源行号的安全义务票据，票据只收紧、不放宽宿主审批；网络出口门禁逐项检查收件人、对象和金额，可信监视器记录效果，确定性解码器决定是否放行。作者在三个未修改 Agent 框架上报告 overlook/overkill 均为 0.0%。
- **主要观点**：模型可以提出义务，但不应由模型决定最终规则；决定器和执行证据必须在模型外部。
- **可信度/局限**：页面标注“Submitted to ICLR 2027 (Under review)”；结果依赖作者的恶意/良性 Skill 对和观察范围，不能视为通用零风险保证。
- **对学习/求职的价值**：适合作为“来源→义务→副作用→证据”网关原型，重点补测绕过、观测盲区、恢复和审计完整性。
- **来源**：[arXiv:2611.03772](https://arxiv.org/abs/2611.03772)

### 4. VeriHarm-Bench：任务成功与安全成功必须分开（arXiv v1）

- **事实/创新**：基准对良性编码任务做最小扰动，自动生成可执行伤害测试，同时检查任务正确性和副作用；作者报告 GPT‑5.6‑Sol、Claude‑Opus‑5 等前沿 Agent 平均任务准确率 95%，但安全成功率仅 37%。
- **主要观点**：删除无关文件、放宽权限、破坏数据等“有害成功”会被单一任务分数掩盖，安全验收必须看实际状态变化。
- **可信度/局限**：预印本，任务和伤害模板由作者构造；不应把 37% 直接外推到所有 IDE/生产环境。
- **对学习/求职的价值**：这是最适合落地到个人项目的评测模板：任务成功、允许副作用、禁止副作用、回滚时间四个指标必须同时报告。
- **来源**：[arXiv:2611.03575](https://arxiv.org/abs/2611.03575)

### 5. 其他安全研究补充

- **Goal-harm conflict**：论文把“为保护被分配目标而采取伤害行动”统一为 goal-harm conflict，并区分 logit preference 与开放式行为的 sampling view；它是对齐评测框架，不是现实事故报告。[arXiv:2611.03374](https://arxiv.org/abs/2611.03374)
- **基准裁判审计**：八个同行评审多模态基准的官方 scorer 在相同输出上可造成最高 22 个百分点差异；盲法人类+LLM 仲裁的 Cohen’s κ=0.956，说明解析器和 abstain 规则本身应纳入复现审计。[arXiv:2611.03377](https://arxiv.org/abs/2611.03377)
- **图数据投毒认证**：ST-GPA 通过伪标签和合成边增强图分区，目标是对节点标签与图结构训练数据中毒给出认证；目前页面只给出方法和“跨基准提升保证”的摘要级结论，需读正文核查攻击预算与证书覆盖。[arXiv:2611.03350](https://arxiv.org/abs/2611.03350)
- **感染后行为图**：37 个恶意软件家族的 CAPEv2 动态轨迹被建模为异构图，作者报告集成分类器准确率 94.44%、MCC 0.863，并用 LLM 生成基于 MITRE ATT&CK 证据的分析；这属于传统恶意软件取证补充，不应混写成模型中毒事件。[arXiv:2611.03774](https://arxiv.org/abs/2611.03774)

## 五、给研究生学习与进大厂的行动清单

1. **Agent 安全小项目**：用自有 MCP/RAG/假 AWS policy 做角色签名、权限包络、RuntimeTickets 式运行时门禁和 VeriHarm 式副作用测试；交付攻击前提、成功指标、漏拦/误拦、P95、撤销和回滚证据。
2. **具身方向小项目**：复现 AIRoA/PanoTac/世界模型中的一个受控环节，增加触觉漂移、分布外接触、传感器欺骗、急停和恢复；不要把仿真成功率当作物理安全证明。
3. **评测方法训练**：先读 MCP Tool Poisoning、IAMRAGBENCH、VeriHarm，再把 benchmark scorer、数据 provenance、派生记忆和删除闭包写成可运行检查。
4. **求职表达**：简历用“威胁模型—实验设计—安全×效用—失败复盘—可重放证据”讲项目，明确哪些是预印本复现、哪些是公司自述、哪些尚未验证。
