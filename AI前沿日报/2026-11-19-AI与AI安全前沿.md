## 长期热点回顾

- Agent 安全正在从“提示词是否越界”扩展到**工具副作用、宿主系统调用、共享内存/缓存和多租户隔离**。
- 世界模型的关键约束不只是规划成功率，也包括候选搜索的响应时间、时限、分布转移及低层失手后的恢复。
- 中毒、注入、旁路与侧信道需分清：攻击者能控制什么、触发链路、成功指标、受影响租户和回滚边界不同。

## AI 安全与系统动态

### 1. BlockJack：共享 KV 缓存的地址映射成为多租户隔离面

- **事实**：[arXiv:2611.25945](https://arxiv.org/abs/2611.25945) v1 于 11 月 19 日 11:31 UTC 提交。作者研究分页式 KV 缓存的块映射，报告受控故障可使一个请求读取另一租户的缓存块，在七个模型上观察到隐私信息暴露及受害者回答受异租户上下文影响。作者还报告曾向 vLLM 与 Sonar 负责任披露并复核所提修补；本次没有找到维护者对该具体研究的独立公告。
- **主要观点/创新点**：模型参数、提示词和 KV 内容即使未被直接修改，**缓存地址翻译**仍能成为保密性与完整性风险；把传统内存隔离审计延伸到推理服务的块表。
- **可信度/局限**：预印本、特定硬件故障与服务配置；不能据此断言普通远程 API 用户可触发或生产平台已受攻。论文医疗场景中最高 41.1% 的不充分紧急建议是受控评测，不是临床事故率。
- **学习与求职价值**：审计推理栈时记录租户绑定、KV 分配/释放、块映射校验、重放与异常隔离；做合成跨租户测试，避免接触真实用户数据。

### 2. Tether：根据真实系统副作用执行有状态策略

- **事实**：[arXiv:2611.25599](https://arxiv.org/abs/2611.25599) v1 于 11 月 19 日 06:46 UTC 提交。Tether 在一次性沙箱中试执行 Agent 提议的操作，从系统调用抽象出真实副作用，并用 Lean 4 DSL 执行跨多步的信息流、访问和网络策略。作者报告在其编码 Agent 基准中阻止全部预设范围内攻击，正常任务误报低于 5%。
- **主要观点/创新点**：只看 shell 文本或单次工具权限会漏掉脚本内部网络请求和跨步数据流；基于观察到的副作用与历史状态做独立门禁。
- **可信度/局限**：“100%”只限论文预设攻击与可观察语义；系统调用抽象、沙箱与正式执行环境可能不一致，生产并发及性能仍需验证。
- **学习与求职价值**：做一个无真实副作用的安全网关：预执行、记录文件/网络/进程效果、验证策略、再决定提交；测漏拦、误拦、P95 和撤销恢复。

### 3. ToolPulse：本地工具调用可能泄露任务轨迹

- **事实**：[arXiv:2611.25470](https://arxiv.org/abs/2611.25470) v1 于 11 月 19 日 03:57 UTC 提交。作者将共享缓存侧信道应用于本地 Agent 工具执行，在其 11 个模型及 Codex/Claude Code 的受控评测中报告工具工作流重建 F1 最低仍高于 93%，并研究任务类别及敏感操作时点的推断。
- **主要观点/创新点**：模型推理在云端不意味着端到端隐私；工具在本机调用共享库，可能通过宿主侧信道暴露工作流形状。
- **可信度/局限**：需要合适的本机或共享硬件观察条件；论文实验不等于已经发生实际数据窃取，且仅重建工具轨迹而非完整用户文本。
- **学习与求职价值**：将 Agent 隐私威胁模型延伸到本地进程隔离、共享主机调度、执行节律与敏感操作监控；只在授权机器做评估。

## 具身智能单列观察

### 1. Verify2Act：动作执行前用潜在世界模型验证计划

- **事实**：[arXiv:2611.25243](https://arxiv.org/abs/2611.25243) v1 于 11 月 18 日 22:22 UTC 提交。VLM 提出多步操作计划，潜在世界模型在 DINOv2 特征空间预测结果，双头 critic 检查时间一致性与目标达成。作者在六项语言条件实机任务报告 83.3% 成功率，对照 VLM 单用为 53.3%。
- **主要观点/创新点**：把语义提议与物理可行性验证分离；潜在预测减少像素级世界模型的成本，并在下发动作前提供检查点。
- **可信度/局限**：模型与 critic 据数字孪生数据训练、实机任务有限；作者称失败来自低层抓取/放置，提醒高层计划验证并不保证接触安全或执行成功。
- **学习与求职价值**：比较无验证、静态检查与潜在世界模型检查的成功率、误拒、规划 P95、低层失手和恢复时间。

### 2. Fast-JEPA：世界模型规划的成功率—时延共同优化

- **事实**：[arXiv:2611.25927](https://arxiv.org/abs/2611.25927) v1 于 11 月 19 日 11:09 UTC 提交。作者用目标导向计划引导搜索、直接预测完整候选动作序列结果，减少递归 rollout；在四个任务上报告平均成功率 96.50%、规划速度为对照 INTACT 的 2.41 倍，并提出含分布转移和执行期限的 DynaGoal 评测。
- **主要观点/创新点**：世界模型规划不能只比较无限搜索预算下的成功率；候选评估、时限和控制延迟决定可部署性。
- **可信度/局限**：受控任务与作者基准，不能外推真机实时安全或复杂长程接触；平均速度不替代 P95/最坏时延。
- **学习与求职价值**：将搜索预算、动态 OOD、P50/P95/截止时间违约率、碰撞/超力率列入同一 Pareto 图。

## 中毒与侵入观察

| 方向与前提 | 攻击链及成功指标 | 防御与边界 |
|---|---|---|
| 多租户推理服务缓存映射受故障影响 | 跨租户 KV 读取或错误上下文影响输出；测泄露率、回答完整性与影响范围 | 校验请求—物理块绑定、隔离和异常处理；BlockJack 是论文实验，具体补丁仍待维护者原文核准。 |
| Agent 有权运行脚本或工具 | 多步副作用越出文件/网络/权限策略；测真实系统调用和最终效果 | Tether 式预执行与状态策略、审计、拒绝后恢复；对照预执行与正式执行差异。 |
| 本机或共享主机可观察共享缓存 | 工具调用节律泄露任务类别与敏感操作阶段；测重建 F1 和跨硬件迁移 | 主机隔离与敏感负载调度、泄露面评估；不把轨迹推断误写成训练数据中毒。 |

**本窗口未核验到新的真实训练数据、权重、RAG 或长期记忆投毒事件，也未独立证实机器人在野入侵。**
