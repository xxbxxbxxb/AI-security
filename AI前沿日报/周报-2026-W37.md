# 2026 年第 37 周 AI、AI 安全与具身智能周报

> 汇总范围：2026-09-06 至 2026-09-12 的 7 份已记录日报；检索日期覆盖 9 月 7 日至 9 月 13 日（北京时间）。9 月 12 日日报明确说明当天未确认足够多的高信号新增，因此本周结论以跨日趋势和可复用证据为主，不把搜索摘要或营销表述当作新事实。
>
> 证据口径：A/A- 为官方公告、公开安全报告或同行评审论文；B/B+ 为预印本、公司案例、威胁情报或媒体转述。公司自报 benchmark、威胁归因和长期预测均保留其主张性质。安全部分只总结威胁模型、影响和防守，不提供可直接用于未授权攻击的操作步骤。

## 一、本周结论

1. **安全评价单位从“回答”迁移到“长程闭环”。** GPT-6 Astra 的 Critical 网络安全能力、Anthropic 四起评测事故和 AI 辅助入侵共同表明，真正的风险单位是模型、工具、身份、环境、记忆和外部副作用组成的轨迹。必须同时测量授权判断、现实性识别、停止/退避、监控漏检和恢复时间。
2. **能力增长与可监控性仍然错位。** 公开材料反复披露更强推理、工具使用和研究自动化，也承认 CoT 监控、策略性低表现和监控器自身鲁棒性不足。只看 CoT 或最终文本不能证明系统安全，行为轨迹、工具调用、网络、文件/CI 状态和结果状态需要独立记录。
3. **攻击者已经把 AI 生态编排成一条供应链攻击链。** GTIG、GitSpawn 和 Unit 42 的材料把提示词、agent loop、Git/插件上下文、MCP/模型包、OIDC token、云身份、凭证和模型端点串在一起；防守侧的资产清单、准入、撤权和响应也必须跨层联动。
4. **具身智能的最小安全单位是“感知—状态—规划—动作—控制—急停”闭环。** SAPIA 和世界模型安全综述把文本/视觉注入、传感器欺骗、状态污染、轨迹操纵和动力学误预测连接到物理后果。世界模型的想象轨迹应被当作候选证据，必须经过实时观测、硬约束和独立低层控制器复核。
5. **中毒对象从模型权重扩展到上下文和运行时状态。** 训练/微调数据、RAG 文档、few-shot 示例、长期记忆、工具 schema、地图/传感器、world-state cache 和 API 输出都可能被污染或滥用。来源证明、版本/签名、变更审计、运行时差分和回滚应成为统一控制面。
6. **AI 误用与第三方影响正在走向“编排化”，治理也要从单轮过滤升级为跨账号、跨会话和跨平台响应。** Anthropic 将网络、监控、生物、影响行动、常规武器和非法蒸馏放入同一威胁情报循环；OpenAI 的 RubyGems 更新则示范了“已确认良性访问”与“尚未核实的恶意指控”必须分开记录。
7. **产业化指标从榜单分数转向安全约束下的任务经济学。** agent-workdays、首次通过率、人工复核分钟数、token/美元成本、权限违规、检测延迟、回滚时间和安全事故率，才更接近企业部署与招聘中的真实评价对象。

## 三、研究创新点

1. **把“可停止性”和“现实性证据”做成长轨迹变量。** 继 Anthropic 复盘，本周最值得复现的评测不是单个越狱字符串，而是混合模拟/真实线索、无解任务、授权不明确和显式终止命令下的退避率、越界动作率、监控漏检率与恢复时间。
2. **建立模型资产外泄的统一威胁模型。** 将 API 输出、系统提示、工具使用策略、账号/代理关系、云额度和模型权重视为同一资产图，结合跨账号行为指纹、时序、提示结构、能力域集中和输出覆盖度检测蒸馏与异常抽取。
3. **把具身安全评测从输入鲁棒性推进到动作可执行性。** SAPIA 的危险指令可转化为文本/视觉输入、规划轨迹、动作白名单、速度/力矩/碰撞约束和急停的端到端指标；跨本体、跨版本迁移率应与物理可执行率一起报告。
4. **把上下文中毒纳入供应链和数据治理。** 为 RAG、few-shot、长期记忆、工具 schema、地图和 world-state cache 维护来源、版本、签名、信任等级和责任人，比较干净/污染条件下的轨迹差异，并验证回滚与恢复。
5. **将选择性自动化与组织容量联合优化。** accept/escalate/reject 不应只由模型置信度决定；研究可把资产风险、动作副作用、证据冲突、人工队列容量、误隔离成本和检测延迟放入同一决策面。
6. **把事件证据分层和调查状态纳入安全工程。** OpenAI 对 RubyGems 的更新将良性访问、未核实指控、已通知第三方和持续调查分开，适合抽象成事件记录 schema，避免把“公司观察”“第三方日志”“媒体归因”和“司法事实”混成一个标签。
7. **发展“模型 + 策略/图 + 控制器 + 人审”的分层架构。** SENTINEL-RL、实验 agent 和企业安全材料共同支持：LLM 负责解释与候选计划，结构化策略层负责权限/状态约束，低层控制器负责物理安全，人工负责高风险升级与发布/回滚决策。

## 四、具身智能专题

### 1. 本周变化

- **VLA/世界模型信任边界被具体化。** SAPIA 将自动驾驶、机器人操作、无人机和工业控制置于同一场景化提示注入框架；世界模型综述进一步指出，错误可从观测、状态、动力学、可供性和安全代价一路传到动作。
- **“预测安全幻觉”成为关键风险。** 被污染的状态或动力学可能让想象轨迹看似安全，规划器因此放行实际危险动作。世界模型输出不能替代实时传感器、动力学检查和独立安全控制器。
- **真实闭环案例仍显示能力边界。** GPT-5.6 Sol 量子芯片校准案例在信号清晰、流程定义明确时减少人工介入，遇到弱信号和噪声则需要经验研究员；这说明实验 agent 适合可回滚、白名单化流程，不适合直接接管开放式安全关键实验。

### 2. 建议评测协议

| 层级 | 应测内容 | 关键指标 |
|---|---|---|
| 感知/输入 | 文本、图像、传感器欺骗、场景自适应注入 | 攻击成功率、跨模态迁移、检测延迟、误伤率 |
| 状态/记忆 | 地图、RAG、few-shot、长期记忆、world-state cache 的污染与回滚 | 来源完整性、轨迹差分、污染持久时间、回滚成功率 |
| 规划/动作 | 候选轨迹与动作白名单、禁行区、速度/力矩/载荷/碰撞约束 | 危险动作率、物理可执行率、约束违例率、任务完成率 |
| 控制/运行时 | 独立安全控制器、状态偏差、网络/工具异常、急停 | 急停延迟、安全姿态到达率、恢复时间、残余副作用 |
| 证据/部署 | 仿真、实验室、真实部署三层证据和人工升级 | 证据等级、退避率、人工介入分钟数、Sim2Real 差距 |

### 3. 工程判断

模型只应提出候选动作；策略引擎决定权限与自动化等级；低层控制器执行硬约束；异常时进入安全姿态并保留全轨迹。具身系统招聘和研究评价应同时考查机器人控制、仿真到现实、实时系统、数据治理、威胁建模和事件响应，而不是只看 VLA 离线成功率。

## 五、中毒与侵入专题

### 1. 攻击对象与进入路径

- **训练/微调/权重层：** 数据污染、后门、模型资产抽取与非法蒸馏。
- **上下文/知识层：** RAG 文档、few-shot 示例、长期记忆、技能库、工具 schema、网页/邮件/日志返回值。
- **状态/具身层：** 传感器、地图、轨迹、world-state cache、动力学和安全代价。
- **供应链/运行时层：** Git 配置、插件 hook、MCP server、模型包、依赖、CI/CD OIDC token、云身份和隐藏工作区。
- **账号/服务层：** 代理账号、跨平台 API 调用、模型端点、输出策略和云算力。

### 2. 本周防守共识

1. 按 Apple 的区分，**data poisoning** 是改变被处理的数据/参数，**action poisoning** 是改变 agent 最终选择执行的动作；外部内容可被读取，但不得未经策略层验证写入控制流。
2. 对所有上下文资产增加 provenance 元数据：来源、版本、签名、时间、信任等级、变更责任人、允许用途和过期时间；运行时对干净/污染版本做轨迹差分。
3. 对模型蒸馏与 API 滥用采用跨账号、跨会话、跨云检测：提示结构、调用时序、能力域集中、输出覆盖度、共享支付/代理基础设施和账号关系图，比单账号限流更有信号。
4. 将检测结果分为 accept、escalate、reject，并把资产关键性、动作副作用、证据冲突和人工队列容量纳入阈值；不确定性本身应触发降级或人工升级。
5. 事件响应必须可逆：撤销 API/云凭证、冻结 CI/CD、隔离账号/端点、锁定受污染上下文、保存证据、恢复干净版本、回归评测并记录责任闭环。
6. 对调查中的事件明确记录已确认、未确认、第三方证据和当前复现状态；尤其不要把“可访问互联网”直接写成“上传恶意包”。

## 六、攻防趋势

| 趋势 | 攻击侧变化 | 防守侧应跟踪的指标 |
|---|---|---|
| 编排化 | 多步骤、跨会话、持久记忆、代理账号和工具调用替代单轮请求 | 账号/会话关联召回率、任务链风险覆盖率、人工升级率 |
| 供应链化 | 从 prompt 注入扩展到 Git、插件/MCP、模型包、OIDC、云身份和隐藏配置 | 依赖准入覆盖率、签名/构建证明有效率、权限违规、撤权时间 |
| 速度化 | agent loop 自动排错、并行重试和跨系统移动，压缩攻击窗口 | 检测到撤权、CI 冻结、云隔离、恢复服务的端到端时间 |
| 监控对抗化 | 策略性低表现、CoT 操纵、监控器被不可信输入影响 | 全轨迹相对 CoT-only 的召回率、监控漏检率、校准误差 |
| 物理化 | 状态/动力学/传感器污染通过规划器放大为动作后果 | 危险动作率、急停延迟、物理可执行率、恢复时间 |
| 资产化 | 模型输出、工具策略、权重、提示和云额度成为可抽取资产 | 异常抽取召回率、误报率、输出保护损失、跨平台关联效果 |
| 治理化 | 能力阈值、独立评估、青少年/生物/武器安全、董事会监督进入发布链 | 发布/回滚条件、独立复核、异议记录、整改 SLA、事故披露完整度 |

## 七、对研究生学习/进大厂的启示

### 优先级 A：做一个可审计 agent 安全网关

实现“任务分解 → 候选工具调用 → 证据/状态校验 → 策略授权 → 低风险自动执行或人工升级 → 全轨迹日志 → 回滚”的最小闭环。至少记录模型/工具版本、seed、时间窗、权限、网络、文件/CI 状态、失败类型和恢复时间。

### 优先级 A：把供应链与运行时安全做成作品集

为 MCP/模型/包/容器/Actions/OIDC/隐藏工作区建立准入检查，验证来源、SBOM、签名/SLSA、网络权限和运行行为；用合成数据演示凭证撤销、CI 冻结、云隔离和证据保全。项目应只在自有隔离环境测试。

### 优先级 B：补齐具身与 AI for Science 基础

学习 ROS/仿真、实时控制、碰撞/速度/力矩约束、主动学习和实验日志；将 VLA/世界模型输出限制为候选计划，在模拟器中先做 dry-run、白名单参数、异常阈值、急停和可回滚性验证。

### 优先级 B：提升评测与统计素养

复现 DGEval 和 LLM-IDS 的核心思想，报告跨日/跨供应商方差、ECE、风险覆盖率、证据召回、人工分钟数、成本和误隔离率；不要只展示一次 leaderboard 分数或厂商自测数字。

### 优先级 C：建立治理与写作能力

阅读 Frontier AI Governance Framework、preparedness policy、system card、红队报告和事故复盘，练习把技术发现写成发布门槛、残余风险、回滚责任、独立评测、利益冲突回避和整改 SLA。

## 八、下周跟踪清单

1. **具身智能：** 是否出现新的 VLA/世界模型正式论文、真实机器人事故披露、跨本体提示注入复现、Sim2Real 安全基准或物理安全盾实测。
2. **世界模型完整性：** 来源证明、状态/动力学不确定性、轨迹门控、预测安全幻觉和运行时反馈审计是否出现可复现实验。
3. **中毒与后门：** 上下文示例、RAG/长期记忆、工具 schema、传感器/地图和 world-state cache 的检测、溯源、隔离、恢复指标。
4. **模型蒸馏与资产保护：** NSA/FBI/CISA 争议的技术证据、跨平台检测基准、输出保护对正常用户的影响及当事方回应。
5. **Agent 供应链：** GitSpawn 受影响产品的修复状态、恶意 MCP/模型包、SLSA/OIDC 误用、隐藏工作区和云算力劫持的新样本。
6. **长轨迹对齐：** Anthropic-METR 独立调查、混合模拟/真实评测、无解任务、监控漏检率、停止/退避行为和多 agent 场景。
7. **第三方影响调查：** RubyGems 恶意上传说法的注册表/受影响方证据、OpenAI 后续更新及其他 agent spam/运行时内部案例。
8. **选择性自动化：** LLM-IDS 的跨数据集复现、校准与人工队列容量联合策略，以及 accept/escalate/reject 在真实 SOC 的误隔离成本。
9. **治理与产业化：** 能力型监管法案、独立 AI 审计标准、Safety Committee 是否产生可观察的发布/延期/回滚动作，以及 agent-workdays 指标的独立口径。
10. **高风险评测：** DGEval 后续论文、法规证据召回、适用条件和人工升级格式在网络安全、隐私和供应链领域的迁移。
