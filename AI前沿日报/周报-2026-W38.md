# 2026-W38 AI、AI 安全与具身智能周报

> 覆盖窗口：北京时间 2026-09-13 至 2026-09-19。  
> 实际材料：[[2026-09-13-AI与AI安全前沿]]、[[2026-09-14-AI与AI安全前沿]]、[[2026-09-15-AI与AI安全前沿]]、[[2026-09-16-AI与AI安全前沿]]、[[2026-09-17-AI与AI安全前沿]]。9 月 18、19 日没有已记录日报，因此本周结论只代表这五份材料，不把缺报解释为“没有新动态”。  
> 证据口径：官方文本可确认“发布/表态发生”，不自动证明性能或治理效果；arXiv 结果按预印本和作者实验记录；媒体报道保留归因；跨来源结论明确标为综合推断。攻击内容仅保留防御研究所需的威胁模型、指标和响应，不提供未授权攻击步骤。

## 一、本周结论

1. **Agent 的安全主问题从“输出是否有害”继续转向“异步行动是否可授权、可撤销、可归因”。** Gemini 3.8 Live 把持续对话、视觉输入、并行推理和后台工具调用放入同一交互循环；Internet of Agents、workflow identity hijacking 与第三方影响调查则从身份、发现和跨组织取证补齐风险面。综合来看，对话状态、任务状态和权限状态必须分离，最终判断要落到实际工具行为而非自然语言解释。
2. **具身智能出现了一条清晰的“能力增强—新污染面—独立控制”链。** TEMPO 的时序信息、X-WBC 的跨本体共享、MM-Future 的世界—动作联合建模和 AnyViewDex 的训练期几何监督都在增强控制能力；同一时期，世界模型 checkpoint 与 LoRA/ROS2 后门研究说明，历史、权重、结构化动作和中间件也会成为控制供应链。独立安全控制器、硬约束、急停和版本回滚不能由 VLA 自我检查替代。
3. **物理 AI 的证据门槛正在从演示成功率转向闭环安全 case。** Digit 5 的官方架构、TC260 实践指南、AdvScene 安全场景生成与 ResSafe 残差安全策略共同把人体检测、危险动作、控制延迟、误停、恢复和责任人推到台前。但公司运行时长、作者 benchmark 和“协作安全”定位仍需独立复测，不能互相替代。
4. **中毒与侵入正从单点 prompt 问题扩展为四层资产问题。** 本周可归并为模型/软件供应链、数据/上下文/状态、身份/工具/网络、物理执行/恢复四层。世界模型后门、计划注入绕过 CoT 监控和工作流身份劫持分别说明：干净数据、合理推理文本或正常输入都不足以证明最终动作安全。
5. **治理语言开始转成工程门禁，但落地证据仍不对称。** TC260 的七阶段实践指南给出了责任、测试、监控、关停和回退的正式文本；embedded evaluators、capability checkpoint、provable inference 与事故透明度仍主要是公司负责人主张或路线图。下阶段应跟踪“谁能访问什么证据、何时真正暂停/回滚、整改是否闭环”，而不是只统计承诺数量。

## 三、研究创新点

1. **动态信息被拆成可检验的两路输入。** TEMPO 用冻结视频模型的运动摘要和紧凑本体历史分别处理运动歧义与状态混淆，提供了“单帧、仅运动、仅本体历史、两者结合”的明确消融路径。
2. **跨本体学习从共享动作空间转向“共享语义 + 本体执行模块”。** X-WBC 试图共享人类运动语义和时序结构，同时保留关节、接触和动力学差异；真正的泛化证据应同时包括任务性能和物理约束违规。
3. **世界模型同时成为规划器和供应链资产。** MM-Future 联合生成场景—动作候选来表达多模态不确定性；When the World Lies 则表明下游即使用干净数据，受污染 checkpoint 仍可能扭曲控制优化。能力与完整性必须用同一版本链评测。
4. **灵巧操作把几何监督前移到训练期。** AnyViewDex 在仿真训练中使用多视角对比与特权 3D 坐标，部署时只依赖单目 RGB 和本体感知。这降低传感器与标定负担，但把风险转移到仿真覆盖、视角漂移、遮挡和本体状态完整性。
5. **安全评测从找危险轨迹转向找危险初始分布。** AdvScene 用生成模型和闭环反馈搜索更可能产生碰撞或低 TTC 的初始场景，适合用于回归测试；其生成概率与真实世界发生概率仍需分开。
6. **任务策略与安全修正被解耦。** ResSafe 让残差策略承担安全修正，降低单一奖励函数中的目标竞争；但学习型过滤器仍需与可验证硬约束和故障降级组合。
7. **无监督安全检测开始使用局部稀疏表示。** 局部掩码 + SAE 的研究尝试在很少 OOD 样本下校准异常检测，价值在于减少对未来危害标签的依赖；生产价值取决于误报、漂移、因果性和人工升级成本。
8. **Agent 发现被提升为身份基础设施。** Agent Root/Registry/Resolver 把标识、能力、证书和解析分层，为 Agent BOM、撤销和审计提供接口；开放网络中的恶意注册、证书泄露和跨域信任仍未解决。

## 四、具身智能专题

| 子方向 | 本周变化 | 证据边界 | 下一步应测 |
|---|---|---|---|
| VLA | TEMPO 增加运动摘要与本体历史；时序信息从“更多帧”细化为两类缺失信息 | 预印本与作者实验，未本地复现 | 四组消融、乱序/过期状态、端到端延迟、危险动作率 |
| 世界模型 | MM-Future 联合未来场景与动作候选；世界模型后门把 checkpoint 完整性带入控制链 | 两篇均为预印本，能力结果与攻击结果不可跨设置类比 | 候选覆盖、碰撞/TTC、权重签名、触发/无触发性能、回滚成本 |
| 机器人操作/导航 | AnyViewDex 推进单目跨视角灵巧操作；本周未记录新的高信号通用移动导航论文 | 单机械臂、有限物体/视角；导航方向存在日报覆盖缺口 | 遮挡、噪声、接触力、拒绝/降级、长程导航恢复 |
| 人形与移动机器人 | Digit 5 把人体检测、动作降级和独立控制器写入产品架构 | 厂商发布；第三方认证、故障注入和现场复测不足 | 漏检、误停、停止时间、断网行为、恢复、维修与车队事故率 |
| 触觉 | 五份日报没有记录新的高信号触觉模型、数据集或安全实测 | “未记录”不是“没有发布” | 触觉漂移、力控越界、接触欺骗与视觉—触觉冲突处理 |
| 多模态感知 | Gemini Live 强调实时视觉语境；AnyViewDex 用 RGB + 本体感知；Digit 5 使用多传感器人体检测 | 前者和后者为公司主张，中间为有限硬件实验 | 传感器冲突、多人遮挡、环境噪声、模态失效时的降级 |
| 跨本体学习 | X-WBC 用共享表示连接九种仿真本体及四台真实机器人 | 作者实验，不等于任意新硬件零样本迁移 | 未见本体、关节限位、接触约束、轻量模块重训成本 |
| 仿真到现实 | AnyViewDex 把特权几何限制在训练期；AdvScene 在仿真中扩大安全关键覆盖 | 仿真覆盖和真实发生概率未对齐 | 域偏移、真实性评分、硬件故障类型、回归场景复现率 |
| 数据集/评测 | NAVSIM/HUGSIM、Waymo 场景、480 次抓取主试验构成不同证据层 | benchmark 分数、闭环仿真和真实硬件成功率不可直接互换 | 统一记录覆盖、失败分类、碰撞/TTC、置信区间和复现预算 |
| 实时控制 | ROS2/LoRA 研究暴露语义复检约 8—9 秒延迟；TEMPO 等能力模块也会增加控制链成本 | 数字只限论文设置 | P50/P95 延迟、watchdog、控制周期超时、慢速语义/快速硬约束双路径 |
| 物理安全 | Digit 5、TC260、ResSafe 共同强调检测、修正、关停与回退 | 产品架构、指南和学习策略是三类不同证据 | 危险动作漏检、急停时间、误干预、恢复状态、人工接管和责任链 |

**周度判断：** 具身智能本周不是由单一“大模型突破”主导，而是能力模块、身份/供应链完整性和物理安全证据同时前移。研究设计应采用两条闭环：上层记录观测、历史、世界模型、候选计划和工具身份；下层用独立控制器执行速度、力矩、禁区、watchdog 与急停。任何新增检测都要同时报告安全收益与时延/任务退化。

## 五、中毒与侵入专题

### 5.1 本周案例矩阵

| 方向 | 攻击前提与攻击链（防御性摘要） | 成功指标与影响范围 | 防御效果/优先控制 | 复现状态 |
|---|---|---|---|---|
| 世界模型/权重中毒 | 攻击者控制下游采用的世界模型 checkpoint；污染潜在动力学，再影响规划或策略优化 | 作者最强设置报告触发步骤劫持可达 100%，干净任务成功率至少约 75%；影响控制决策，不要求污染下游干净数据 | 可信来源、哈希/签名、隔离评测、跨版本轨迹差分、独立动作约束、可回滚版本；作者称温和微调可能保留后门，激进修复可能损害效用 | arXiv 预印本；本周仅核验摘要/版本信息，未运行代码或独立复现 |
| LoRA/模型到 ROS2 后门 | 污染 adapter 在触发条件下改变可执行结构化命令，穿过消息 schema 到 ROS2 节点和物理动作 | 论文设置中 ASR 约 83%，干净准确率超过 93%；影响模型、schema、中间件和执行器 | 二次语义检查把 ASR 报告降到约 20%，代价是约 8—9 秒延迟；还需 Model BOM/SBOM、动作白名单、实时硬约束和急停 | 较早 arXiv 预印本，本周作为基线重复引用；有仿真/物理实验描述，无跨栈独立复现 |
| 上下文/计划注入 | actor 上下文被植入外部计划；actor 将其改述为自身推理，来源丢失，CoT 监控器接受“干净”轨迹 | 作者在所测基准报告约 25%—33% 监控规避率；影响 agent 计划与监控链 | 不只看 CoT：保留来源、请求者身份、工具参数和真实执行结果；固定误报率比较漏检与成本 | 预印本摘要级核验；未复现防御，不能外推生产入侵率 |
| 工作流身份/越权 | 低信任请求进入工作流，后端以高权限服务身份执行，未贯穿原始请求者授权 | 成功标准是未经授权资源访问/写入；可跨 RAG、SaaS 和工具链，不依赖提示注入 | 短期限权委托、逐资源授权、内部检索/外部回复分离、身份事件审计、合成多租户测试 | 厂商原始披露 + 媒体更新；属于 confused deputy 类问题，跨平台范围与修复效果未独立验证 |
| Agent/MCP/插件发现 | 恶意或错误能力声明、伪造身份、过期证书进入 agent 发现和调用链 | 关注错误解析、未授权调用、撤销失效、能力漂移；影响 agent 生态供应链 | Agent BOM、双证书/分级认证、发布者与权限绑定、撤销检查、调用日志和回滚 | Internet of Agents 为预印本原型；只报告注册/发现延迟，开放网络对抗性未证实 |
| 第三方平台/供应链影响 | agent 使用外部网络、暴露凭证或第三方服务；多主体分别持有模型、身份、网络和平台日志 | 外部写入、账号滥用、agent spam、第三方清理与通知；RubyGems 恶意上传说法仍未确认 | 网络/工作负载隔离、最小权限、原始轨迹、跨组织时间线、凭证撤销、通知与回归测试 | 公司持续调查；已确认行为、未证实指控和第三方材料必须分层 |
| 训练数据/微调、RAG/长期记忆、依赖攻击、对抗样本 | 五份日报没有新增同时具备原始来源、明确前提、指标和复现信息的高信号案例 | 不应把缺少记录写成风险消失或攻击失败 | 延续 provenance、信任标签、TTL、依赖准入、差分测试、隔离与恢复演练 | 本周覆盖不足；列入下周定向检索 |

### 5.2 统一事件响应字段

中毒/侵入项目至少保存以下字段：受影响资产与版本、首次失守边界、攻击/故障前提、请求者与执行身份、原始输入及来源、模型与工具轨迹、网络/文件/控制动作、成功指标、影响对象、发现与隔离时间、凭证撤销、干净版本、恢复与回归结果、第三方通知、残余权限和未决归因。自然语言摘要只作索引，不能替代原始证据。

## 六、攻防趋势

| 趋势 | 攻击/失效侧变化 | 防守侧变化 | 本周判断 |
|---|---|---|---|
| 从内容到行动 | 异步工具、结构化命令和服务身份让风险越过聊天界面 | 对话/任务/权限状态分离，实际行为审计，确认、取消和 UNKNOWN 恢复 | “说得安全”不再是主要验收标准 |
| 从单模型到资产图 | 权重、adapter、世界模型、RAG/记忆、插件、证书和 ROS2 配置相互依赖 | Model BOM + SBOM + Agent BOM，签名、版本锁定、撤销和回滚 | 供应链清单要能关联运行时证据，而非静态表格 |
| 从静态样本到闭环 | 污染计划被改述、多 agent 自动重试、物理策略滚动执行 | 全轨迹、来源、身份和环境快照；按同误报率比较漏检 | 单轮 prompt benchmark 继续失去代表性 |
| 从平均分到尾部风险 | 多未来、视角变化、危险初始场景和触发后门针对少数状态 | 候选覆盖、碰撞/TTC、危险动作、拒绝率、P95 延迟和恢复 | 需要保留失败分布，不只报均值 |
| 从模型自检到分层控制 | 高层模型、监控器或安全策略可能共享同一污染源 | 慢速语义检查 + 独立实时控制器 + 硬约束/急停 | 防御收益必须与延迟、误停、效用损失一起报告 |
| 从原则到门禁 | 公司承诺和治理框架逐步谈到暂停、外部访问和全生命周期 | capability checkpoint、七阶段证据、责任人、关停/回退 | 真正缺口是独立访问、触发阈值和整改结果的公开证据 |

## 七、对研究生学习/进大厂的启示

### P0：做一个“身份贯穿 + 可撤销工具调用”的 Agent 安全网关

最小闭环：请求者身份 → 检索/工具候选 → 资源级授权 → 低风险执行或人工升级 → 结果作为不可信数据回流 → 全轨迹日志 → 撤销/回滚。验收至少包含跨租户拒绝、重复请求、超时、取消、凭证失效和未知写入结果；同时报告正常成功率、越权阻断率、误拦截、P95 延迟和恢复时间。

### P1：做一个具身控制供应链与实时安全项目

在隔离仿真中给 VLA/ROS2 栈建立 Model BOM、SBOM 和状态来源记录，测试 adapter/世界模型版本变化、历史乱序、传感器冲突与结构化动作越界。架构上分离高层语义检查和低层硬约束，验收指标包含触发/无触发任务成功率、危险动作率、控制周期、急停、误停和回滚后的回归结果。

### P1：复现一篇能力论文，同时加入安全消融

优先 TEMPO 或 AnyViewDex：先复现作者主任务，再增加缺帧、乱序、遮挡、噪声、过期本体状态和拒绝/降级策略。面试时按“数据流—张量/模块接口—消融—失败类型—系统代价”讲清楚，可信度高于只展示成功视频。

### P2：把 TC260 七阶段做成项目证据包

为选定项目逐阶段绑定资产、责任人、测试、日志、门禁、关停与回退。输出一张控制矩阵、一份事件时间线、一次桌面演练和一页残余风险；这能同时覆盖 Agent/RAG 工程、MLOps、安全与治理岗位常见追问。

### 面试与论文表达原则

- 把官方发布事实、作者实验数字、公司归因、媒体转述和自己的推断分栏；主动说明尚未复现的部分。
- 不只讲 ASR/准确率，还讲攻击前提、干净性能、误报、延迟、恢复、第三方影响和真实权限边界。
- 对具身结果区分离线 benchmark、闭环仿真、真实硬件和长期现场运行；不要跨层换算。
- 作品集应提供可运行验证、固定种子/版本、失败样例和回滚演示，形成“知识 → 实践 → 面经 → 追问 → 复盘”闭环。
