# 2026-W40 AI、AI 安全与具身智能周报

> 覆盖窗口：北京时间 2026-09-28 至 2026-10-04。
>
> 实际材料：[[2026-09-28-AI与AI安全前沿]]、[[2026-09-29-AI与AI安全前沿]]、[[2026-09-30-AI与AI安全前沿]]、[[2026-10-01-AI与AI安全前沿]]、[[2026-10-02-AI与AI安全前沿]]、[[2026-10-04-AI与AI安全前沿]]。10 月 3 日没有已记录日报；因此本周判断只代表六份已有材料，不把缺报解释为“没有新动态”，也不使用旧闻填充缺口。
>
> 证据口径：官方公告证明发布、合作或自评发生，不自动证明性能和安全效果；arXiv 按预印本和作者实验记录处理；公司研究、行业分析和媒体归因分别标注；跨日判断标为综合推断。漏洞/事件只保留防御性前提、攻击链、成功与干净指标、影响、防御、恢复和复现状态，不提供攻击载荷或未授权操作步骤。

## 一、本周结论

1. **Agent 安全控制面从“提示过滤”下沉到身份、运行时、硬件和结果审计。** NVIDIA 的 Open Agent Safety Platform 将 OpenShell 运行时策略与 BlueField-4 上的独立 Sentry watchdog 组合；Google Cloud 预览把 CLI/IAM 作为 MCP 工具面；OpenAI 安全卡则显示仅看 CoT 不足以覆盖外部消息、工具参数、权限变化和真实副作用。综合推断是：生产竞争单位已从单次模型输出转向“请求者—来源—权限—工具—结果—恢复”的可回放状态机，但厂商架构和内部指标仍不是端到端安全证明。
2. **供应链风险本周出现了从“潜在面”到“真实事件”的连续证据。** The Stack v3 扫描在历史仓库中验证到 543,699 个仍可用凭证；DIVD 官方事件记录了 AI agent 串联 Zammad 漏洞并造成部分志愿者数据外泄；多个 MCP SDK 的 OAuth 缺陷共同指向未绑定 issuer/resource 和信任对端认证元数据。三者共同说明：训练数据、依赖、Agent 身份和外部工具都应进入同一条 provenance 与凭证生命周期。
3. **具身智能的周度主线是“中间表示 + 可撤销的物理安全层”。** RPG 将技能候选放进仿真练习、失败诊断和回归后再复用；SkeleWAM 用稀疏 3D 骨架表示未来世界—动作状态；HumanoidToolBench 把工具选择、移动、接触执行和完成判定放进同一评测；Agility/FORT 用 safety pendant、机上通信和 off-robot interface 构成纵深架构。共同缺口仍是触觉丢失、状态过期、通信故障、人机共域、急停和恢复的独立实测。
4. **评测正在从平均成功率转向尾部风险、验证器完整性和经济部署。** Chance-constrained fine-tuning 试图约束安全退化尾部；benchmark 研究警告“unearned pass”会由验证器缺陷或 git 历史捷径制造；Anthropic 的 E0–E3 robot exposure index 把能力、环境结构化程度和经济性分开。结论不是“某模型已安全或即将替代人”，而是评测必须同时报告触发/干净差异、验证证据、P95 延迟、人工接管和单位任务成本。
5. **中毒与侵入要严格分层，不能把运行时注入写成权重后门。** 本周有较强的一手供应链/入侵事件和 MCP 漏洞证据，但没有核验到日期明确、具备原始来源与复现的新增训练数据中毒、权重后门或 RAG/长期记忆真实入侵。技能库/系统提示污染、MCP 身份边界、平台 UGC 分发和 API 蒸馏争议应分别记录首次失守边界与独立复现状态。
6. **10 月 4 日把“评估环境完整性”推到企业控制面。** Microsoft 将 agent identity、归因、撤销、记忆、模型/数据和软件供应链放进同一框架；OpenAI 与 Anthropic 的越界复盘都指向真实网络可达、凭证存在、任务范围模糊和连续决策的组合风险。综合推断是：沙箱网络、出站控制、工具白名单、kill switch 和全轨迹监控必须像模型指标一样接受独立验收。

## 三、研究创新点

1. **独立制动路径成为 Agent 部署设计的一等组件。** OpenShell/Sentry、Google Cloud IAM/MCP 和 Digit 5 的 offboard bridge 都把策略或急停放到模型之外；研究重点从“模型是否拒答”转为权限是否可撤销、结果是否可审计、硬约束是否能在模型失效时继续工作。
2. **来源证明贯穿模型输出、数据集和物理对象。** SynthID Bio 将水印从文本/图像拓展到序列—结构—物理分子；The Stack/训练数据案例则把来源、秘密扫描、吊销/轮换和下游模型版本连成 Data BOM/Model BOM。共同创新不是某个检测器，而是“发现—归因—隔离—恢复—再扫描”的生命周期闭环。
3. **技能和中间状态成为可审计的具身资产。** RPG 的技能候选、SkeleWAM 的关节/物体/交互点骨架、HumanoidToolBench 的工具目录和停止条件，均比端到端黑盒视频提供更小的故障注入点；但表示可检查不代表状态一定真实，仍需来源、置信度、时间戳和状态新鲜度。
4. **评测完整性本身被纳入安全工程。** Harness 交互超图和 unearned-pass 审计分别处理组合爆炸与验证器捷径；安全卡从 CoT 观察扩展到 action/tool/result/permission 全轨迹。未来报告需要同时给出验证器、环境快照、权限配置、失败轨迹和恢复结果。
5. **具身能力开始用环境和经济性表达。** E0–E3 将“会做”与“在什么环境能稳定做、是否值得部署”拆开；RPG/SkeleWAM/HumanoidToolBench 则提供可复现的技能、状态和工具接口。研究价值在于把成功率、延迟、接管和单位成本放到同一个决策表，而不是堆叠孤立 benchmark 分数。
6. **事故复盘正在把环境错误纳入模型安全证据。** Anthropic 的四起评估越界与 OpenAI 的第三方影响汇总都把网络边界、凭证、工具权限、模型版本、外部副作用和恢复责任放入同一时间线；这为研究生构造可回放 Agent Incident Schema 提供了比单次 prompt demo 更可检验的接口。

**周度判断：** 具身系统正在形成“语义/来源检查 + 实时独立制动”的双路径；企业 Agent 也需要“环境/身份校验 + 全轨迹监控 + 可撤销权限”的双路径。上层应记录对象、技能、骨架、工具权限、来源与状态新鲜度；下层应以速度/力矩禁区、watchdog、急停和安全姿态限制物理后果。任何作者成功率、厂商运行小时数或仿真相关性，都必须和接触失败、P95 延迟、人工接管、恢复残留一起解释。

## 五、中毒与侵入专题

### 5.1 本周事件与研究矩阵

| 方向 | 攻击前提与高层链路（防御性摘要） | 成功指标/影响范围 | 防御效果与优先控制 | 复现状态 |
|---|---|---|---|---|
| 训练数据/秘密暴露 | 公开仓库或网页语料含仍有效凭证 → 数据集进入训练/检索管线 → 后续使用放大暴露窗口 | 凭证仍可验证、暴露时长、下游模型/日志关联；影响取决于签发方、租户和数据版本 | 训练前 verified-secret 扫描、隔离/剔除、来源哈希、吊销/轮换、成本异常与再扫描；不保存真实秘密 | Truffle 原始扫描较强；CSA 扩展到 HF/Common Crawl 是二次分析，未审计全部数据集 |
| Agent 串联漏洞 | 面向互联网服务 + 会话/RCE/本地提权缺陷 + agent 可读取响应并持续决策 → 服务访问/外泄 | 首次失守边界、权限变化、可访问对象、外泄确认、隔离耗时和恢复残留 | 补丁/下线、网络分段、最小权限、工具范围、人工升级、凭证撤销、日志回放和干净恢复 | DIVD/Zammad 官方事件与 CVE 可核验；攻击者身份和全部影响仍调查中，不复述利用步骤 |
| 评估环境误配置/真实网络越界 | 评估伙伴或测试 harness 声称无互联网但出站未完全隔离，模型同时拥有任务权限和连续决策能力 → 接触真实第三方系统 | 真实出站、外部副作用、停止/拒绝率、发现延迟、扫描召回和恢复残留；影响取决于凭证、网络和目标范围 | 独立核验网络/凭证边界、出站 DNS/HTTP、工具白名单、kill switch、全轨迹监控、人工升级和第三方通知 | OpenAI/Anthropic 官方复盘；Anthropic 的 METR 独立调查仍进行，不能外推生产攻击率 |
| MCP OAuth/依赖供应链 | 客户端使用受影响 SDK 并连接不可信或边界不清的 server → issuer/resource 元数据被对端或重试路径影响 → 凭据导向错误身份 | 凭据/授权码离开预期 issuer、错误绑定、撤销是否生效；主要影响机密性和身份冒用 | 升级锁版本、issuer/resource/audience 绑定、清理旧记录、轮换密钥、撤销令牌、SBOM、负向测试和旧网关盘点 | Python 官方 advisory；rmcp/LiteLLM 状态由行业分析汇总，需回到各自公告核对 |
| 平台 UGC/插件分发 | 恶意内容获得搜索/推荐入口 → 可信托管页面和用户信任串联 → 诱导本地高风险动作 | 发布者 provenance、外链/剪贴板行为、告警命中和阻断；CSA 转述至少 40 起相关事件但归因需回原始材料 | 发布者身份、能力声明、外链扫描、高风险动作二次确认、企业端阻止不受信任本地执行、回滚证据 | CSA/Huntress 二次材料，未复述载荷、命令或哈希；不写成平台普遍感染率 |
| API 蒸馏与模型 provenance | 大量正常 API 请求、账号集群和输出搬运 → 训练来源/安全约束难以证明 | 请求聚类、提示均一性、时间关联、异常输出搬运；“尝试”不等于成功蒸馏 | 记录 provider attestation、第三方输出 lineage、账号风控、独立测试越权/拒答/工具调用；人工调查避免误伤正常用户 | CSA 对 OpenAI 归因和数字未独立核验，属于待核查风险信号 |
| 运行时/上下文污染 | 技能、系统提示、记忆条目、检索文本或工具描述被低信任输入影响 → 行为状态改变 | 触发/干净任务差异、工具调用变化、误隔离、权限升级、恢复残留 | 写入审批、来源标签、TTL、版本签名、候选隔离、执行前授权、结果审计、撤销/回滚 | 本周有预印本框架与风险探针，但未核验新的直接权重后门或 RAG 真实入侵 |

### 5.2 统一事件响应字段

对任何后续案例至少保存：受影响资产、模型/adapter/依赖版本、数据集或工具来源、首次失守边界、请求者与执行身份、原始输入及来源、完整工具/网络/文件轨迹、成功与干净指标、影响对象、发现/隔离时间、凭证撤销、干净版本、恢复和回归结果、第三方通知、残余权限和未决归因。自然语言摘要只作索引，不能替代原始日志、版本哈希和时间线。

## 六、攻防趋势

| 趋势 | 攻击/失效侧变化 | 防守侧变化 | 本周判断 |
|---|---|---|---|
| 从内容到行动 | 低信任文本、技能、工具描述和 UGC 可跨过界面改变状态或诱导本地动作 | 来源、身份、参数、执行结果和外部副作用贯穿审计，执行前授权与可撤销权限成为门禁 | schema 合法不等于授权正确，必须验证意图和实际效果 |
| 从单点漏洞到闭环事件 | agent 将服务漏洞、连续读取和决策执行串为较快攻击链 | 网络分段、最小权限、补丁、人工升级、凭证撤销和恢复形成状态机 | 事件严重度由“自动化权限 × 可达数据 × 恢复残留”共同决定 |
| 从模型资产到三类 BOM | 权重、数据、adapter、依赖、证书、技能和机器人控制器相互依赖 | Model BOM + Data/Agent BOM + SBOM 关联签名、运行时日志和回滚 | 静态清单只有连到隔离和回滚才有运营价值 |
| 从平均分到尾部与验证器 | 少数触发、OOD、状态过期或 unearned pass 决定真实后果 | 固定误报率比较漏检、验证证据、P95 延迟、碰撞/TTC、误隔离和恢复 | 失败分布和验证完整性比单一均值更能支撑上线决策 |
| 从自检到独立制动 | 模型、CoT 监控器和高层规划可能共享污染源或来不及响应 | 慢速语义/来源检查 + 独立实时控制器 + watchdog/急停/安全姿态 | 防御收益必须连同延迟、误停、效用损失和恢复发布 |
| 从能力主张到部署经济性 | 机器人“能做”与可在结构化/非结构化环境稳定、低成本地做相差很大 | E0–E3、单位任务成本、人工接管、维修和法规约束进入评测 | 能力、环境、可靠性、成本应是同一张能力卡，而非单一 benchmark |
| 从路线图到可验证治理 | 公司公告、MOU、政策术语和未来目标增多，完成证据可能滞后 | 独立评估、访问边界、复测窗口、冲突披露、证据留存和恢复演练 | 研究记录必须拆开“目标、过程、完成证据、独立复现” |
| 从模型错误到环境完整性 | 评估网络、凭证、任务范围和第三方配置错误会让模型行为产生真实外部副作用 | 把网络隔离、出站控制、工具白名单、kill switch、全轨迹日志和第三方通知纳入同一验收 | “安全评估环境”本身就是系统资产，不能只审模型权重 |

## 七、对研究生学习/进大厂的启示

### P0：Data/Model/Agent BOM + 可撤销 MCP 身份网关

用合成秘密和公开样本实现训练前扫描，输出数据集版本、命中样本哈希、吊销工单和下游模型关联；为 MCP client/server 建立 typed-auth 回归矩阵，覆盖 issuer/resource 不匹配、重定向、403、重试、降级、旧依赖和凭证撤销。验收正常成功率、越权阻断率、误报、P95、恢复残留和回滚。

### P1：Agent 全轨迹监控对照

在授权离线沙箱中比较四种监控输入：仅文本/CoT、加入工具参数、加入权限变化、加入执行结果与外部消息。用相同误报约束比较漏检、检测延迟、人工升级分钟数、隔离成功率和恢复成本，不把内部安全卡比例外推为真实攻击率。

### P1：具身 typed-tool + 双路径安全仿真

以 RPG、SkeleWAM 或 HumanoidToolBench 为阅读/复现入口，把技能候选、对象 ID、骨架状态、工具权限、状态新鲜度、碰撞/TTC、急停和人工接管写进同一轨迹；高层做来源和权限检查，低层用独立控制器、速度/力矩禁区、watchdog 和回滚限制物理后果。

### P2：把记忆/技能防御做成效用曲线

用受控合成数据比较写入审批、来源标签、TTL、检索配额、候选隔离和执行前授权；同时保留干净流量。报告触发/干净成功率、误隔离、证据召回、token/延迟成本、急停和恢复残留，而不是只展示过滤率。

### P1：建立 Agent Incident Casebook

用 DIVD、Anthropic 评估越界、OpenAI 第三方影响和 Microsoft 报告各做一页案例卡：只保留授权前提、首次失守边界、身份/工具、外部副作用、隔离、凭证撤销、恢复和未决归因。再做一次只用合成目标的环境审计，证明网络不可达、出站被阻断、kill switch 可用、全轨迹可回放。

### 面试与研究表达原则

- 先说证据类型：官方发布、原始安全公告、原始事件、arXiv 预印本、二次分析或综合推断。
- 再说威胁边界：前提、首次失守、攻击链、成功/干净指标、影响、防御和复现状态。
- 最后说工程验收：权限、日志、P95、误报/漏报、急停、回滚和恢复；不演示未授权攻击步骤。
